集合类

集合（Set）抽象数据类型映射了经典数学理论中的集合概念。集合被定义为一个由互异值组成的无序集合。

集合类支持底层的原子操作，例如添加元素、移除元素以及测试元素的存在性；以及并集、交集、差集、子集判断以及集合的相等性测试等数学运算。

集合关系运算

集合的比较首先体现在相等性与差异性上。判断两个集合是否相等，充分必要条件是两个集合互为子集。

集合相等不要按“内存表示是否一样”来判断，而要按“成员资格是否一样”来判断。也就是说，两个集合即使底层一个用树、一个用哈希表，只要任意元素对二者的 contains 结果完全一致，它们在抽象数据类型层面就是同一个集合。因此用“互为子集”实现相等判断，本质上是检查两个集合有没有遗漏或多余的元素。

集合代数运算

并集操作将两个集合的元素合并，消除重复项；交集操作筛选出双边重叠的元素；差集操作则执行严格的剔除逻辑。

指针与泛型排序

在集合的底层实现中，系统必须能够比较指定值类型的元素。对于诸如整数和字符串的内置类型，内置的 == 和 < 运算符已经足够。然而不可避免地会遇到用户定义的复合数据结构，由于这些复合类型未必重载了关系运算符，良好的软件接口设计需要允许客户端作为集合构造函数的一部分，主动注入自定义的比较法则。

冯·诺伊曼架构提出了存储程序模型。在这一模型中，执行运算的指令代码与运算所处理的数据被统一存储在相同的物理内存中。这意味着，每一个 C++ 函数的机器指令流在进程的内存空间中占据着一个确定的物理地址。既然函数本质上是内存中的一段连续数据，高级语言便可以声明一个指针变量来存储这个起始地址，进而在运行时动态地跳转和调用这块内存区域中的逻辑。

集合数据结构

实现集合这一抽象概念时，有两种选择：

  1. 哈希表： 利用哈希函数将元素映射到连续内存空间（桶）。其主要优势在于较高的性能，提供平均时间复杂度为 O(1)O(1)O(1) 的元素添加和成员资格测试操作。然而，哈希策略的弱点在于它破坏了元素的内在顺序，无法支持按照值类型规定的顺序进行迭代输出。
  2. 平衡二叉树： 诸如红黑树或 AVL 树结构，均提供最坏情况下的 O(log⁡N)O(\log N)O(logN) 性能保障。虽然单次操作的渐进复杂度劣于哈希表，但它保持了严格的节点偏序关系，使得开发有序迭代器成为可能。

特征向量与字符集合

当集合实现被发布给客户端后，遥测数据可能揭示出某些特定类型的集合被高频调用，值得为其引入专用且复杂的数据结构优化。在编译器设计或词法扫描器的开发中，经常需要定义一系列由定界符组成的字符集合（Set<char>）。

对于这种值域空间有限的数据类型（如仅有 256 个状态的 ASCII 字符集），利用树结构或哈希表会产生较高的对象管理开销。应对此类场景的常见解法是采用特征向量或称位向量。

特征向量的核心思想在于：对于小整数或字符集，可以使用内存中的单独一个“位（Bit）”来表征元素的存在性状态。状态 1 表示包含，状态 0 表示排除。由于每一个 ASCII 码都可以映射为从 0 到 255 的绝对偏移量，一个包含所有大小写字母的集合，可以被压缩进一段仅占用 256 位的连续内存区块中。

CPU 能够将特征向量的大块位序列载入寄存器中，并利用机器指令级别的按位运算符执行集合代数计算。这种优化使原本需要成百上千次循环迭代的并、交、差运算，可通过极少数机器指令并发完成。

运算符 描述与位级操作行为 在特征向量集合代数中的映射意义
& 按位与： 对齐的两操作数对应位同为 1，结果位才为 1，否则为 0。 集合交集： 只有同时属于两个集合的元素，其特征位才会保留为 1。该技术在底层常被称为掩码（Masking）截取。
| 按位或： 对齐的两操作数对应位只要有一个为 1，结果位即为 1。 集合并集： 合并两个特征向量，使得出现在任一集合中的元素均被标记。
^ 按位异或： 对齐的两操作数对应位的值不相同，结果位即为 1。 集合对称差： 提取属于集合 A 或属于集合 B，但不同时属于二者的元素。
~ 按位非： 单操作数取反，0 变为 1，1 变为 0。 集合的补集： 标记所有未被当前集合涵盖的全集元素。
<< 左移： 所有位整体向左移动，低位补 0。 用于快速定位和生成特定元素的特征掩码（如 1 << charValue）。
>> 右移： 所有位整体向右移动（无符号数执行逻辑移位）。 用于快速扫描或状态降维。

结合上述运算符，可以组合出复杂的集合操作。例如，欲计算集合 AAA 与集合 BBB 的差集（即出现在 AAA 中但不属于 BBB 的元素），可以通过公式 A & (~B) 实现。首先利用 ~B 计算出不属于 BBB 的所有元素的超集特征向量，随后将其与 AAA 的特征向量进行 & 掩码计算，过滤出的最终状态序列即为差集的结果。

特征向量的关键是把“元素是否存在”从一次对象查找压缩成一次位判断。例如字符 c 的 ASCII 码为 99，就把第 99 位看作 c 的存在标记。集合运算于是变成了整段机器字上的并行位运算：CPU 一次 & 或 | 处理的不是一个元素，而是一组元素的存在状态。

布隆过滤器

特征向量通过牺牲值域的普适性，在有限空间内实现了较高性能。然而建立特征向量所需内存会非常大；若使用哈希表等传统数据结构存储原始数据来避免误差，内存成本同样可能过高。

布隆过滤器牺牲了少量准确性换取了对大规模数据集进行成员资格测试时较高的内存压缩效益。

定义

布隆过滤器是一条初始状态全部为 0 的位数组，长度设定为 mmm。除此之外，有 kkk 个相互独立的哈希函数集 h1,h2,…,hkh_1, h_2, \dots, h_kh1​,h2​,…,hk​。这 kkk 个函数需要具备较好的随机离散性，确保能将任意输入的复杂元素均匀地映射到 {0,1,…,m−1}\{0, 1, \dots, m-1\}{0,1,…,m−1} 的离散值域索引内。

  • 插入： 当客户端希望将新元素 xxx 注入到集合中时，系统会将 xxx 分别抛入 kkk 个哈希函数中，计算出 kkk 个离散的整型索引。随后，系统跳转至位数组中对应的位置，将这 kkk 个位置的比特位全部翻转为 1。由于没有任何机制记录是哪一个具体元素修改了某个特定位置，不同的元素完全可能将同一个比特位重复置为 1（哈希碰撞）。

  • 查询：当系统需要检验未知元素 yyy 是否隶属于该集合时，将以相同的规则对 yyy 进行 kkk 次哈希映射。

    • 确定排除： 如果在探测过程中，这 kkk 个目标索引位置存在任何一个是 0，布隆过滤器就能确定元素 yyy 不在集合中。因为如果它曾被插入，这 kkk 个位置早应在历史操作中全部被置为了 1。这就是布隆过滤器的的无假阴性。
    • 概率存在： 反之，如果探测发现 kkk 个目标位均已被置为 1，系统只能返回元素 yyy 可能在集合中的推测。因为随着集合越来越拥挤，这 kkk 个位置有极高概率是由其它若干个不相关元素在历史插入过程中凑巧覆盖的结果。这种将非成员错误判定为成员的情况，即为假阳性。

    布隆过滤器的查询结果只有两种语义：“一定不存在”和“可能存在”。它不会把已经插入过的元素误判为不存在，因为插入只会把位从 0 改成 1，不会反向清空；但它可能把没插入过的元素误判为存在，因为多个元素的哈希足迹可能刚好把相关位置都覆盖成 1。参数 mmm 控制位数组空间，nnn 控制已插入规模，kkk 控制每个元素留下多少个哈希足迹，三者共同决定误报率。

假阳性率

假设所有哈希函数相互独立，且生成的索引分布足够均匀，可以得到如下规律：

  1. 单次映射后的空闲概率： 在执行一次单独的哈希操作时，位数组中某一个特定的比特位被恰好击中并置为 1 的概率是 1m\frac{1}{m}m1​。相反，该特定位成功躲过此次修改，维持状态 0 的概率为：

    1−1m1 - \frac{1}{m} 1−m1​

  2. 单个元素插入后的空闲概率： 当一个完整的元素被插入时，连续触发了 kkk 次独立哈希。这期间该特定位依然没有受到任何波及而保持 0 的概率是：

    (1−1m)k\left(1 - \frac{1}{m}\right)^k (1−m1​)k

  3. n 个元素插入后的空闲概率极限： 经过 nnn 个不同元素的插入，总共执行了 knknkn 次映射。该位在整个过程中始终未被置为 1 的精确概率是：
    $$\left(1 - \frac{1}{m}\right)^{kn}$$

    mmm 通常是一个极大的数值。由 lim⁡x→∞(1−1x)−x=e\lim_{x \to \infty} (1 - \frac{1}{x})^{-x} = elimx→∞​(1−x1​)−x=e，可以对上述离散概率进行近似：

    (1−1m)kn=[(1−1m)−m]−knm≈e−knm\left(1 - \frac{1}{m}\right)^{kn} = \left[ \left( 1 - \frac{1}{m} \right)^{-m} \right]^{-\frac{kn}{m}} \approx e^{-\frac{kn}{m}} (1−m1​)kn=[(1−m1​)−m]−mkn​≈e−mkn​

    因此，在过滤器吸收了所有 nnn 个元素之后，任意一个随机比特位已经覆盖为 1 的期望概率（设为 psetp_{\text{set}}pset​）可表示为：

    pset≈1−e−knmp_{\text{set}} \approx 1 - e^{-\frac{kn}{m}} pset​≈1−e−mkn​

当发起对一个未被收录的新元素 yyy 的成员查询时，发生假阳性的前置条件是：yyy 在被 kkk 个哈希函数映射后，所指向的 kkk 个比特位恰好全都在先前的操作中被翻转为了 1。假设这 kkk 个位的状态是互相独立的，发生假阳性误判的概率 fff 为：

f=(pset)k≈(1−e−knm)kf = (p_{\text{set}})^k \approx \left( 1 - e^{-\frac{kn}{m}} \right)^k f=(pset​)k≈(1−e−mkn​)k

通过公式可知：位数组 mmm 越长，哈希空间越稀疏，错误率越低；承载的数据量 nnn 越大，数组越拥挤，错误率越高。哈希函数数量 kkk 的作用更复杂，因为 kkk 同时出现在底数项的指数中，也出现在整个表达式的外层指数中，因此存在一个理论最优值。
