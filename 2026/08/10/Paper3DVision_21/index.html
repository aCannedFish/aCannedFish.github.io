EVER: Exact Volumetric Ellipsoid Rendering for Real-time View Synthesis

发表于2026-08-10|更新于2026-08-17|Note3DVision 论文阅读
|浏览量:

NeRF 与 3D Gaussian Splatting 代表了两种不同的新视角合成路线。NeRF 明确建立连续密度场，沿每条射线求解体渲染积分，几何一致性较好，但大量采样使训练和渲染较慢。3DGS 将场景表示成一组各向异性 Gaussian，通过屏幕空间投影、排序和 alpha compositing 获得很高帧率，却没有真正定义一个与观察方向无关的三维密度场。

3DGS 的近似在普通视角下往往足够好，因此它可以同时获得清晰图像与实时速度。相机连续运动时，近似的边界会更明显：Gaussian 的排序顺序可能突然交换，前后颜色随之跳变，视频中表现为 popping；多个 primitive 在三维空间重叠时，仅按中心深度排序也无法恢复重叠区内真实的混合顺序。StopThePop 在光栅化框架内用层级重排近似逐像素排序 splat；3DGRT 用 ray tracing 找出每条射线命中的 Gaussian particle，并按深度逐个合成。前者仍是 splatting，后者属于 particle ray tracing；二者都没有把 primitive 的相交体积拆成进入、重叠与离开区间，重叠区域的联合密度和颜色因而没有被显式积分。

EVER 将场景改写为一组 常密度实体椭球。每个椭球在三维内部具有固定密度和颜色，射线进入椭球时密度增加，离开时减少；将全部出入事件按距离排序后，射线上的总密度与颜色成为一串分段常数。每个区间都能解析求解体渲染方程，因此无需沿射线做密集数值采样，也无需假设各 primitive 互不重叠。

论文名称中的 Exact 指对这套常密度、无散射的发射—吸收椭球表示做解析积分。在完整收集射线事件的前提下，所定义的 piecewise-constant radiance field 不再引入数值求积、中心排序或忽略 primitive 重叠的近似。

“精确”限定的是给定表示后的积分器。椭球形状、常密度、低阶球谐以及训练得到的场景参数仍是近似，它也没有求解真实材质、多次散射和全局光照。

这个公式本身是标准的前向 alpha compositing，问题来自 αi\alpha_iαi​ 的含义和排序方式。3DGS 的 opacity 是屏幕空间 Gaussian 权重与 primitive opacity 的乘积，同一个三维 Gaussian 从不同方向观察时会得到不同的有效厚度与密度关系。它更接近一个朝向相机的半透明 billboard，无法为任意三维点给出统一密度。

如果两个 primitive 在射线上分别覆盖区间 [tA−,tA+][t_A^-,t_A^+][tA−​,tA+​] 与 [tB−,tB+][t_B^-,t_B^+][tB−​,tB+​]，并且两区间部分重叠，正确的顺序可能是：

A⟶A+B⟶BA\quad\longrightarrow\quad A+B \quad\longrightarrow\quad B A⟶A+B⟶B

按中心排序只能选择“先混 A”或“先混 B”，两种顺序都跳过了中间的 A+BA+BA+B 区间。即使对每个像素单独排序，也只能改善 primitive 的整体前后关系。相机位置略微变化时，中心深度或近似交点的次序可能交换，渲染颜色会产生离散跳变。

这种误差在静态帧中可能被高密度、小尺寸 Gaussian 掩盖，视频或宽基线相机运动更容易暴露。若仅依靠增加 primitive 数量降低 popping，模型存储和排序成本会同步上升。EVER 选择重新定义 primitive 的体积含义，从表示层面消除排序歧义。

实体椭球还具有一个重要性质。沿椭球中心方向观察时，屏幕空间 opacity 的形状由穿越长度决定；增大密度后，轮廓可以从平滑过渡逐渐接近阶跃边缘。3DGS 的二维 Gaussian opacity 总有平滑尾部，很难以单个 primitive 表示锐利边界。EVER 能以较少的高密度 primitive 表达部分清晰结构，也需要专门处理密度饱和后的梯度问题。

这一设计解释了 popping 为何消失。相机连续移动时，交点 tk±t_k^\pmtk±​ 和有效弦长连续变化；射线与椭球从相交过渡到相切时，弦长连续趋于零，因此相切事件本身不会造成有限幅度的颜色跳变，不过导数未必光滑，数值求交精度也仍会影响实现。两个 primitive 的中心深度交换不会改变重叠区 A+BA+BA+B 的存在，颜色不会突然从“先 A”跳到“先 B”。

密度优化

EVER 以 3DGS 的训练框架为基础，从带位姿的多视图图像和稀疏点云初始化 primitive，联合优化位置、旋转、尺度、颜色与密度。直接把一个自由变量映射为 σk\sigma_kσk​ 会产生饱和问题。若密度很大，穿过椭球的 opacity

α=1−e−σℓ\alpha=1-e^{-\sigma\ell} α=1−e−σℓ

趋近于 1，外部内容几乎不可见，损失对 σ\sigmaσ 的梯度也趋近于零。高密度 primitive 可能因此停在不合适的位置和尺度上。

这项映射的设计意图，是让 primitive 沿最短轴方向观察时的峰值 opacity 直接受 αk\alpha_kαk​ 控制，至少有一组观察方向能够保留非零梯度。常数 0.99 避免目标 opacity 真正到达 1，防止 −log⁡(1−α)-\log(1-\alpha)−log(1−α) 发散。

0.99<1−exp(−σ(αk)max⁡(skx,sky,skz))0.99 <1-exp\left( -\sigma(\alpha_k) \max(s_{kx},s_{ky},s_{kz}) \right) 0.99<1−exp(−σ(αk​)max(skx​,sky​,skz​))

满足条件时，说明从主轴方向穿过整个 primitive 已经近乎饱和，训练梯度可能消失，系统会将其拆分。拆分把复杂或过厚区域交给多个较小 primitive 表达，降低单个实体长期遮挡后方内容的风险。

密度控制

3DGS 的 Adaptive Density Control 会周期性地克隆、拆分和裁剪 Gaussian。梯度较大的区域需要更多 primitive，长期不可见或贡献很小的 primitive 可以删除。EVER 沿用这套总体机制，同时针对实体密度做了调整。

首先，EVER 的屏幕空间位置梯度通常小于 3DGS，论文将 splitting 阈值设为 2.5×10−72.5\times10^{-7}2.5×10−7，cloning 阈值设为 0.1。具体阈值依赖实现和梯度缩放，不能直接移植到其他渲染器。

拆分时，子 primitive 的尺寸缩小，中心加入从正态分布采样的扰动。由于两个子椭球初始位置可能重叠，若每个都复制原密度，重叠区域的总密度会近似翻倍。EVER 将密度同时除以 2，使初始总光学厚度更接近拆分前的结果。

其次，ray tracing 的速度与 BVH 包围盒质量密切相关。一个旋转且极细长的椭球可能拥有很大的 Axis-Aligned Bounding Box。许多 AABB 相互重叠时，BVH 无法高效排除无关 primitive，每条射线需要执行更多精确求交。

论文使用各向异性正则：

Laniso,k=stopgrad⁡(1−αk)[max⁡(sk)−min⁡(sk)]\mathcal L_{\mathrm{aniso},k} =\operatorname{stopgrad}(1-\alpha_k) \left[ \max(\mathbf s_k)-\min(\mathbf s_k) \right] Laniso,k​=stopgrad(1−αk​)[max(sk​)−min(sk​)]

它惩罚三个主轴差距过大的 primitive，并只应用于当前 batch 可见的椭球。stopgrad⁡(1−αk)\operatorname{stopgrad}(1-\alpha_k)stopgrad(1−αk​) 只作为权重，不允许模型通过改变 opacity 绕开形状惩罚。低 opacity primitive 受到更强约束，高 opacity primitive 的形状自由度相对更大。

这项正则体现了表示质量与加速结构之间的联系。高度各向异性的 primitive 可能用较少数量贴合细长表面，却会扩大 AABB、降低 ray tracing 吞吐。最终配置对过度拉长的椭球施加约束，以少量表示自由度换取更紧凑的包围盒和更稳定的 BVH 遍历效率。

训练还会在像素内部随机扰动射线位置，避免始终从像素中心采样造成结构化 aliasing。ray jitter 让优化覆盖一个像素对应的连续射线束，使 primitive 边界不会只适配固定的像素中心采样位置。

工程实现

EVER 使用 PyTorch 管理训练，以 CUDA、NVIDIA OptiX 和 Slang 实现可微 ray tracing。每个椭球先计算 AABB 并放入 BVH；射线命中包围盒后，再通过稳定的 ray-sphere 变换求解真实椭球交点。实现还借鉴 3DGRT，在一次 OptiX trace 调用中用队列收集多个 hit，减少重复遍历开销。

每轮训练都要根据当前 primitive 位置与尺度重建 BVH。主要开销来自射线遍历、交点存储以及反向阶段的 primitive 梯度累积，训练过程围绕单个场景独立优化全部椭球参数。

前向阶段需要保存每条射线的最终状态和交点顺序，反向阶段采用 adjoint rendering，从射线末端反向重建各区间状态。这样无需为所有区间保存完整中间函数值，以额外计算换取较低的反向存储成本。primitive 的中心、尺度与旋转梯度来自 ray-ellipsoid intersection 的导数，密度和颜色梯度来自解析体渲染公式。

ray tracing 还让相机模型更灵活。Rasterization 通常先把 primitive 投到固定针孔屏幕，鱼眼投影、景深和每像素多条次级射线都要重新设计投影与 splat 过程。EVER 只需为目标相机生成对应的射线，因此可以直接支持 fisheye camera、像素内随机采样和 aperture sampling 产生的 defocus blur。

这些能力来自射线生成与求交框架，不表示训练数据中未观测区域会自动得到正确几何。鱼眼训练仍需要正确相机标定，景深效果也依赖已经重建出的 radiance field。

实验结果

在 Mip-NeRF 360、Zip-NeRF 等基准上，EVER 的 PSNR 与 3DGS 接近，SSIM 与 LPIPS 通常更好。RTX 4090、720p 下的速度约为 30–66 FPS，表明精确区间积分仍可达到实时级新视角合成。

StopThePop 的 LIP 指标用光流对齐检查视角间的突变：EVER 在较大相机步长下为 0，细小移动下约为 0.003–0.007，优于中心排序或近似逐射线排序方案。完整 entry/exit events 与联合密度积分都是消除排序突变的关键。

特点与局限

EVER 将辐射场表示为常密度实体椭球，每次射线与椭球相交都会产生进入和离开事件，因而可以在相邻事件之间解析计算发射—吸收体渲染积分。该表示能够按照真实重叠区间混合多个 primitive，显著减轻中心深度排序导致的 popping；低阶球谐、基于 OptiX 的射线追踪及沿用自 3DGS 的自适应增密机制，则兼顾了视角相关外观、相机模型灵活性和实时渲染效率。

这里的“精确”仅适用于常密度、仅发射式的椭球模型，并未求解材质 BRDF、多次散射、真实阴影和全局照明；每个场景仍需要已知位姿、稀疏点云及 1 至 2 小时的独立优化。逐射线遍历 BVH、计算并排序交点事件的成本会随 primitive 数量和重叠度增长，模型体积和渲染开销通常也高于 3DGS；此外，方法主要面向静态新视角合成，官方实现对 NVIDIA OptiX、CUDA 和特定 SlangTorch 版本的依赖限制了跨平台部署。
