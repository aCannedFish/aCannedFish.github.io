μ0: A Scalable 3D Interaction-Trace World Model

发表于2026-07-23|更新于2026-08-06|Note读论文：三维重建
|浏览量:

μ0 研究的重点并非从图像恢复一张静态网格，而是从当前观测预测接下来会发生的三维运动。论文把物体、工具、手和接触位置上的少量语义点称为 interaction traces，并把这些点未来的三维轨迹作为世界模型的输出。它位于三维重建与机器人控制之间：前者提供公制三维坐标，后者需要知道任务相关实体将怎样运动。

视频世界模型通常生成未来 RGB 帧，能够描述外观变化，却把大量计算用在背景、纹理与光照上。机器人 VLA 模型直接预测关节或末端执行器动作，但动作空间与具体机械臂绑定，高质量动作标注的规模也远小于普通视频。三维交互轨迹提供了一个更紧凑的中间层：

图像与语言⟶任务相关的三维运动⟶机器人动作\text{图像与语言} \longrightarrow \text{任务相关的三维运动} \longrightarrow \text{机器人动作} 图像与语言⟶任务相关的三维运动⟶机器人动作

轨迹描述“什么位置应该怎样移动”，暂时不规定机械臂用哪种关节运动完成它。μ0 因而可以先从无动作标签的视频中学习通用运动规律，再用少量目标机器人数据训练动作头。

轨迹监督

互联网视频通常没有相机位姿、深度和三维轨迹标注。μ0 为此设计 TraceExtract，将普通视频自动转换为训练样本。整个过程可以概括为：

视频→语义采样二维关键点→三维重建与跟踪全局三维轨迹→事件切分与描述训练片段.\text{视频} \xrightarrow{\text{语义采样}} \text{二维关键点} \xrightarrow{\text{三维重建与跟踪}} \text{全局三维轨迹} \xrightarrow{\text{事件切分与描述}} \text{训练片段}. 视频语义采样​二维关键点三维重建与跟踪​全局三维轨迹事件切分与描述​训练片段.

它使用 DINOv2 找出语义一致的区域，用 VGGT 恢复相机与局部三维几何，再用 TAPIP3D 跨帧跟踪关键点。这里的 VGGT 只参与离线伪标签构建；训练完成后，μ0 并不需要在每次轨迹预测时重新运行完整的视频三维重建。

语义采样

若直接在整幅图像上均匀取点，桌面、墙面等大面积静态背景会占据绝大多数预算，小物体和接触位置反而得不到足够查询。TraceExtract 先对 DINOv2 patch 特征聚类，得到近似的物体或部件分组，再根据相邻帧中的特征相似度和空间重叠进行二分图匹配，将分组传播到整段视频。

每个语义实体得到与可见面积成比例的点数，同时为小实体保留最低配额。实体内部使用 FPS 选择分布均匀的点。这里的 FPS 是 Farthest Point Sampling：先选一个起点，此后每次选取离当前点集最远的候选点。它能以较少的点覆盖整个区域，避免查询集中在局部纹理显著的位置。

条件骨干

μ0 以 SmolVLM2-2.2B 为视觉语言骨干，保留其前 20 个 decoder layer。RGB 图像和语言先被编码为条件 token，并缓存为键和值；Trace Expert 维护一条独立的运动 token 流，通过 cross-attention 读取这些条件。视觉语言骨干与原有 RGB 图像塔被冻结，Trace Expert 和新增加的投影层参与训练。

这种分流结构把两类信息分开：

Fcond=VLM⁡(It,lc),Ztraceℓ+1=TraceBlock⁡(Ztraceℓ,Fcond).F_{\mathrm{cond}} = \operatorname{VLM}(I_t,l_c), \qquad Z_{\mathrm{trace}}^{\ell+1} = \operatorname{TraceBlock} \left( Z_{\mathrm{trace}}^\ell, F_{\mathrm{cond}} \right). Fcond​=VLM(It​,lc​),Ztraceℓ+1​=TraceBlock(Ztraceℓ​,Fcond​).

FcondF_{\mathrm{cond}}Fcond​ 负责场景语义和指令理解，ZtraceZ_{\mathrm{trace}}Ztrace​ 负责连续三维运动。Trace Expert 每两层进行一次查询间 self-attention，并通过 cross-attention 读取冻结 VLM 的 KV cache。它具有 20 层，隐藏宽度约为 VLM 的一半，因此无需重新训练一个完整视觉语言模型。

深度图是可选条件。论文先把公制深度归一化并用 Turbo 色图编码，再通过从 RGB stem 复制而来的可训练 patch stem 输入视觉塔；更深层的 SigLIP 参数仍与 RGB 分支共享。训练时以 0.70.70.7 的概率丢弃深度，使模型不能形成“没有深度就无法工作”的依赖。

查询结构

查询点本质上是无序集合。若用置换矩阵 Π\PiΠ 改变查询顺序，模型应当只改变输出顺序，而不改变每条轨迹：

fθ(ΠQ∣I,l)=Πfθ(Q∣I,l).f_\theta(\Pi Q\mid I,l) = \Pi f_\theta(Q\mid I,l). fθ​(ΠQ∣I,l)=Πfθ​(Q∣I,l).

μ0 对所有点共享同一组网络参数，不加入依赖序号的点 ID。这样训练时可以随机抽取不同数量的查询，推理时也可以为一个小物体增加更多点，而无需改变模型结构。

每个查询包含两类 token：历史轨迹 token 和待生成的未来控制点 token。二者使用不同的 segment embedding。当前二维坐标 (un,vn)(u_n,v_n)(un​,vn​) 经过 Fourier 编码和零初始化 MLP，提供精确位置；同时从冻结 DINOv2 特征图中双线性采样局部特征 fnDINOf_n^{\mathrm{DINO}}fnDINO​：

Fourier 编码告诉模型“查询位于哪里”，DINO 特征告诉模型“这里看起来属于什么实体或部件”。两者结合后，两个空间上相近但语义不同的点不会只因坐标接近而被混为一谈。DINO 特征还与 TraceExtract 中的语义分组形成一致的归纳偏置。

历史信息同样可选。训练时以 0.20.20.2 的概率删除所有历史，并以 0.30.30.3 的概率单独删除某些点的历史。模型由此同时学会三种情况：利用完整运动趋势、在部分点丢失时借助其他点补推、仅根据单帧图像和语言预测。

样条轨迹

样条（spline）是一类用若干低阶多项式片段拼接而成的连续曲线。可以把它想成一根被若干控制点“牵引”的柔性尺：控制点给出曲线的大致走向，曲线在控制点之间平滑弯曲。这里的“样条”不是额外预测的物理实体，而是一种用少量参数表示一整条时间轨迹的数学函数。

这篇论文使用三次 B 样条。三次表示每个相邻时间区间内的曲线是三次多项式，并不表示三维坐标；B 样条中的 B 表示 basis，即用一组固定基函数作为“拼接模板”。将时间归一化为参数 s∈[0,1]s\in[0,1]s∈[0,1]，第 ddd 个控制点 P^n,d\hat P_{n,d}P^n,d​ 对第 nnn 条轨迹的影响由基函数 Bd(s)B_d(s)Bd​(s) 决定：

T^n(s)=∑d=1DBd(s)P^n,d.\hat T_n(s) = \sum_{d=1}^{D} B_d(s)\hat P_{n,d}. T^n​(s)=d=1∑D​Bd​(s)P^n,d​.

在任意固定时刻 sss，这些基函数可以看作一组随时间变化的权重。它们满足

Bd(s)≥0,∑d=1DBd(s)=1.B_d(s)\ge0, \qquad \sum_{d=1}^{D}B_d(s)=1. Bd​(s)≥0,d=1∑D​Bd​(s)=1.

因此，曲线位置是控制点的加权组合。控制点通常不要求落在最终轨迹上；它们更像决定形状的“把手”。例如连续几个控制点整体向右上方移动，解码出的轨迹也会逐步向右上方弯曲。

三次 B 样条还有局部支撑性质：在某个时刻 sss，通常只有附近四个三次基函数非零。因此，移动一个控制点只会改变其附近一段时间的运动，不会重写整条轨迹。多个多项式片段在连接处具有连续的一阶、二阶导数，意味着位置连续、速度连续，且加速度不会突然跳变。这很符合抬起、移动、放下等大多数机械操作的运动规律。

语义流

同一张图像和同一句指令可能对应多种合理未来。例如手可以从杯子左侧或右侧接近，物体也可能沿不同路径绕过障碍。用均方误差直接回归一条轨迹，会把多个模式取平均，得到一条不属于任何真实示范的中间路线。

μ0 在 B 样条控制点空间学习条件分布。设干净控制点为 P⋆P^\starP⋆，标准高斯噪声为
ϵ∼N(0,I)\epsilon\sim\mathcal N(0,I)ϵ∼N(0,I)，插值状态为

论文的时间方向中，τ=0\tau=0τ=0 是干净轨迹，τ=1\tau=1τ=1 是纯噪声。沿这条直线的真实速度为

dPτdτ=ϵ−P⋆.\frac{\mathrm dP^\tau}{\mathrm d\tau} = \epsilon-P^\star. dτdPτ​=ϵ−P⋆.

Trace Expert 接收带噪控制点、时间 τ\tauτ 和条件特征，回归这一速度：

Lflow=E[∥vθ(Pτ,τ,Fcond)−(ϵ−P⋆)∥22].\mathcal L_{\mathrm{flow}} = \mathbb E \left[ \left\| v_\theta \left( P^\tau,\tau,F_{\mathrm{cond}} \right) - \left( \epsilon-P^\star \right) \right\|_2^2 \right]. Lflow​=E[∥vθ​(Pτ,τ,Fcond​)−(ϵ−P⋆)∥22​].

流匹配学习的是每个噪声状态应该向哪种合理轨迹移动。训练数据中的多种拿取方式、路径和接触过程共同决定条件分布；推理时不同初始噪声会沿速度场到达不同高概率区域，因此可以采样多个合理未来。流模型本身不会自动保证物理正确，它之所以趋向真实运动流形，是因为速度场只接受真实视频轨迹拟合出的 P⋆P^\starP⋆ 作为终点监督，并由图像、语言、局部语义和结构损失共同约束。

结构损失

视频片段可能在动作结束前终止，点也会因遮挡永久消失。若强迫所有轨迹都预测到固定的第 32 帧，模型会在无监督区域继续任意运动。μ0 为每个查询点预测 HHH 个有效性 logit，并用 BCE 监督：

yn,k=1y_{n,k}=1yn,k​=1 表示该时间步仍有有效轨迹，000 表示已经结束。BCE 即二元交叉熵：

ℓBCE(d^,y)=−ylog⁡σ(d^)−(1−y)log⁡(1−σ(d^)).\ell_{\mathrm{BCE}}(\hat d,y) = -y\log\sigma(\hat d) -(1-y)\log\left(1-\sigma(\hat d)\right). ℓBCE​(d^,y)=−ylogσ(d^)−(1−y)log(1−σ(d^)).

流匹配负责多模态运动分布，B 样条负责时间平滑，有效性头处理轨迹终止，刚性损失维护同一物体内部的空间结构。四部分分别解决不同问题，彼此不能完全替代。

动作适配

轨迹世界模型只预测“交互点应当怎样移动”，还不能直接驱动机械臂。论文在预训练完成后冻结 VLM 和 Trace Expert，另外训练一个与目标机器人动作空间对应的 Action Expert。

Action Expert 并不等待 μ0 完成四步采样后再读取最终轨迹。它从随机控制点出发执行一次部分去噪，取 Trace Expert 的中间隐藏状态 ztracez_{\mathrm{trace}}ztrace​。这些特征同时包含当前图像、语言、查询点和“合理未来运动”的信息，比一条已经离散化的最终轨迹保留更多不确定性。

轨迹特征先被投影到 VLM 隐空间：

h~trace=LN⁡(Wprojztrace).\tilde h_{\mathrm{trace}} = \operatorname{LN} \left( W_{\mathrm{proj}}z_{\mathrm{trace}} \right). h~trace​=LN(Wproj​ztrace​).

zguided=z+σ(g)CrossAttn⁡(Q=LN⁡(z),K=V=h~trace).z_{\mathrm{guided}} = z+ \sigma(g) \operatorname{CrossAttn} \left( Q=\operatorname{LN}(z), K=V=\tilde h_{\mathrm{trace}} \right). zguided​=z+σ(g)CrossAttn(Q=LN(z),K=V=h~trace​).

ggg 是可学习标量，门控使动作网络能够逐步调节轨迹信息的强度。Action Expert 还读取腕部相机图像的 DINOv2 特征、机器人本体状态、语言和带噪动作。

ADE 小表示全过程接近真值，FDE 小表示最终到达位置准确。DTW 使用动态时间规整，在允许局部时间快慢变化的条件下寻找两条轨迹的最小匹配代价，适合区分“路线正确但执行速度不同”和“几何路径本身错误”。

流模型可以从不同噪声生成多个结果。Top-1 使用一个样本，Top-5 则从五个样本中取与真值最接近的一个：

Metric⁡Top-5=min⁡r=1,…,5Metric⁡(T^r,T⋆).\operatorname{Metric}_{\mathrm{Top}\text{-}5} = \min_{r=1,\ldots,5} \operatorname{Metric} \left( \hat T_r,T^\star \right). MetricTop-5​=r=1,…,5min​Metric(T^r​,T⋆).

方法联系

μ0 与前面几篇三维重建工作的关系可以分成三个层次：

  1. VGGT 从多帧图像中恢复相机、深度和 point map，为 TraceExtract 提供公制坐标与跨片段对齐的几何骨架。
  2. TraceExtract 在静态几何上增加时间对应关系，将“每一帧哪里有表面”转化为“同一个语义点怎样随时间移动”。
  3. μ0 在大量轨迹样本上学习条件运动分布，再由 Action Expert 将这一中间表示翻译为特定机器人的动作。

NOVA3R、VolFill 和 Surflo 都使用生成模型补全观测不到的几何，μ0 则用生成模型处理尚未发生的运动。两者面对的多解性相似：单张图像的隐藏表面存在多种合理解释，当前状态的未来轨迹也存在多种合理走向。VolFill 和 Surflo 在三维几何空间学习流，μ0 在 B 样条控制点空间学习流。训练终点分别来自完整表面或真实视频轨迹，条件分别是图像几何或图像、语言与查询点。

μ0 与直接的 3D tracking 也有本质区别。TAPIP3D 在 TraceExtract 中观察完整视频后恢复已经发生的轨迹，属于离线跟踪；μ0 在只看到当前及可选历史信息时预测尚未发生的未来，属于条件生成。前者负责构造监督，后者负责学习可泛化的动态先验。

相较前作 TraceGen，μ0 不再只依赖固定网格查询和整段视频说明，而是加入语义查询点、全局一致的长程三维轨迹、事件级文本、B 样条表示、语义流模型与可供动作策略读取的中间特征。这些改动共同把“轨迹生成器”扩展为可预训练、可采样并可适配机器人控制的世界模型。

方法特点

  1. 将稠密像素和机器人动作之间的三维交互轨迹定义为通用中间表示，使大规模无动作视频可以参与世界模型预训练。
  2. TraceExtract 结合 DINOv2、VGGT 和 TAPIP3D，从普通长视频自动生成语义点、全局三维轨迹与事件级语言监督。
  3. 用 10 个三次 B 样条控制点表示 32 帧未来，在压缩输出的同时显式引入时间平滑。
  4. 在控制点空间使用条件流匹配，可以从不同噪声采样多种合理未来，避免均方回归造成的轨迹平均。
  5. 通过置换等变查询结构支持 111 到 256256256 个语义点，并允许深度和历史条件缺失。
  6. DINO 局部特征、有效性头与组内刚性损失分别维护语义对应、轨迹终止和物体内部结构。
  7. 冻结 μ0 后用门控 cross-attention 向 Action Expert 注入轨迹特征，通用运动知识与具体机器人控制可以分阶段训练。
