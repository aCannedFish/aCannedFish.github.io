NOVA3R: Non-pixel-aligned Visual Transformer for Amodal 3D Reconstruction

发表于2026-07-23|更新于2026-08-05|Note读论文：三维重建
|浏览量:

VGGT、DUSt3R 一类方法输出的是 pixel-aligned geometry：图像中每个像素对应一个三维点。这个设计让二维外观与三维位置天然建立对应，适合深度估计和匹配，却会留下两个结构性问题。

第一，输出只能描述相机看见的表面。桌子背面、沙发后侧、墙角遮挡区在输入像素中没有位置，也就没有直接的输出槽位。第二，多张图看到同一面墙时，每张图都会生成一份点，微小的深度或位姿误差会把一层墙变成几层相邻的墙。随着视图增加，点数和重复几何一起增长。

NOVA3R 将问题改写为：从无位姿图像预测一组与像素无对应关系的全局三维点。每个场景只保留一份点分布，点可以落在可见表面，也可以落在被遮挡但合理存在的表面。

像素对齐

pixel-aligned point map 可以写成一个从像素格到三维空间的函数：

Pi:Ωi⊂Z2→R3,(u,v)↦Pi(u,v)P_i:\Omega_i\subset\mathbb{Z}^2\rightarrow\mathbb{R}^3, \qquad (u,v)\mapsto P_i(u,v) Pi​:Ωi​⊂Z2→R3,(u,v)↦Pi​(u,v)

它的优势是对应关系容易获得：Pi(u,v)P_i(u,v)Pi​(u,v) 的颜色就是 Ii(u,v)I_i(u,v)Ii​(u,v)，也可以直接知道这个三维点来自哪条相机射线。但一个真实表面点 XXX 若同时被 mmm 张图看见，输出中会出现 mmm 个近似副本：

Pi1(u1)≈Pi2(u2)≈⋯≈Pim(um)≈XP_{i_1}(u_1)\approx P_{i_2}(u_2)\approx\cdots\approx P_{i_m}(u_m)\approx X Pi1​​(u1​)≈Pi2​​(u2​)≈⋯≈Pim​​(um​)≈X

预测完全准确时，副本可以重合；实际只要深度或相机有小误差，它们就会分裂成数层表面，因此产生大量冗余点。将所有 point map 直接拼接的存储量为 O(KHW)O(KHW)O(KHW)，其中 KKK 是视图数，这导致生成的 point 随视角增加线性增长，即使新的视角只携带了少量已有视角没有的信息。

更根本的问题是 visibility。若某点 XXX 在所有输入图像中都被遮挡，就不存在任何 (i,u,v)(i,u,v)(i,u,v) 使 Pi(u,v)=XP_i(u,v)=XPi​(u,v)=X，网络输出结构中根本没有它的位置。逐像素回归可以利用单目先验修正可见深度，却很难自然表达“在所有输入射线后面再生成一层隐藏表面”。

NOVA3R 的输出改成集合：

P^={x^n}n=1Np\hat P=\{\hat x_n\}_{n=1}^{N_p} P^={x^n​}n=1Np​​

集合元素没有所属视图和像素，NpN_pNp​ 也不必等于 KHWKHWKHW。模型只需让这些点整体覆盖场景表面，因此同一墙面可以只保留一层均匀采样，遮挡表面也能拥有独立点。

完整范围

“完整场景”必须先有边界。单张照片外存在无穷大的三维空间，要求模型补全所有不可见区域没有定义。NOVA3R 只重建输入视锥之内的完整表面：

Pcomplete={x∈S  |  x∈⋃i=1KF(Ii)}P_{\mathrm{complete}} =\left\{\mathbf{x}\in S\;\middle|\; \mathbf{x}\in\bigcup_{i=1}^{K}\mathcal{F}(I_i) \right\} Pcomplete​={x∈S​x∈i=1⋃K​F(Ii​)}

SSS 是真实场景表面，F(Ii)\mathcal{F}(I_i)F(Ii​) 是第 iii 个输入相机的视锥。视锥内再区分可见点与遮挡点，视锥外的表面不参与训练和评估。

有网格真值时，可以直接在网格表面均匀采样完整点云。真实场景数据往往只有多视图深度，论文采用近似构造：将密集视角的深度全部反投影到三维，做 voxel-grid filtering 删除重叠点，再裁掉输入视锥外的区域。训练前使用带随机初值的 Farthest Point Sampling，使监督点在场景表面分布得更均匀。

所有目标点都表达在第一张输入图像的相机坐标系中：

P={xn}n=1N,xn∈R3P=\{\mathbf{x}_n\}_{n=1}^{N},\qquad \mathbf{x}_n\in\mathbb{R}^{3} P={xn​}n=1N​,xn​∈R3

这里没有像素索引，也没有规定第 nnn 个预测点必须对应真值中的第 nnn 个点。无序性正是后面引入 flow matching 的原因。

集合损失

无序点云不能直接使用逐索引 L2。假设真值只有两个点 P=(a,b)P=(a,b)P=(a,b)，预测为 P^=(b,a)\hat P=(b,a)P^=(b,a)，两个集合完全相同，但逐索引损失为：

∥b−a∥22+∥a−b∥22>0\|b-a\|_2^2+\|a-b\|_2^2>0 ∥b−a∥22​+∥a−b∥22​>0

常用的 Chamfer Distance 通过最近邻消除排列影响：

CD⁡(P,Q)=1∣P∣∑p∈Pmin⁡q∈Q∥p−q∥2+1∣Q∣∑q∈Qmin⁡p∈P∥q−p∥2\operatorname{CD}(P,Q) =\frac{1}{|P|}\sum_{p\in P}\min_{q\in Q}\|p-q\|_2 +\frac{1}{|Q|}\sum_{q\in Q}\min_{p\in P}\|q-p\|_2 CD(P,Q)=∣P∣1​p∈P∑​q∈Qmin​∥p−q∥2​+∣Q∣1​q∈Q∑​p∈Pmin​∥q−p∥2​

第一项检查每个真值点附近是否有预测点，反映 completeness；第二项检查每个预测点是否贴近真实表面，反映 accuracy。它适合评估，但直接训练大场景生成器有三个问题：

  • 每步都要在两个大点集之间搜索最近邻，计算与显存开销高；
  • 多个预测点可以选择同一个最近邻，损失不会主动保证点分布均匀，可能出现大量点集中在少量真实点附近的情况；
  • 最近邻归属会随点位置突然切换，局部梯度不连续，也缺少“整个点集应该呈现什么全局结构”的生成先验。

Flow matching 将监督改成速度回归。训练时只需知道采样的数据点和噪声点，不要求点云具有固定顺序或显式匹配关系，解决了逐点搜索计算开销大，不保证分布均匀的问题。

点云编码

NOVA3R 分两阶段训练。第一阶段先学习“怎样把完整点云压缩成 scene token，再怎样从 token 恢复点云”，暂时不处理图像。

点云编码器 Φenc\Phi_{\mathrm{enc}}Φenc​ 将 NNN 个点压缩为 MMM 个场景 token：

Z=Φenc(P),P∈RN×3,Z∈RM×C,M≪NZ=\Phi_{\mathrm{enc}}(P),\qquad P\in\mathbb{R}^{N\times3},\quad Z\in\mathbb{R}^{M\times C},\quad M\ll N Z=Φenc​(P),P∈RN×3,Z∈RM×C,M≪N

初始查询同时包含两部分：从真实点云中用 FPS（Farthest Point Sampling：先随机选一个点，之后每一步都选取“距离已选点集合最近距离仍然最大”的点。这样不会把大量查询集中在一面墙或一块稠密区域，而会尽量覆盖场景的不同区域） 选出的 MMM 个点，以及 MMM 个自由学习的 token。将三维坐标做位置编码后与可学习 token 拼接，再线性投影到 CCC 维：

Q(0)=W[γ ⁣(FPS⁡(P)),Qlearn]Q^{(0)} =W\left[\gamma\!\left(\operatorname{FPS}(P)\right),Q_{\mathrm{learn}}\right] Q(0)=W[γ(FPS(P)),Qlearn​]

FPS 查询带着场景的实际空间分布，利于保留细节；可学习查询提供不依赖具体采样点的表达能力，便于处理编码与生成之间的分布变化。消融实验中，混合查询优于只用 FPS 点或只用可学习 token。

编码器沿用 TripoSG 风格：先让查询通过 cross-attention 从完整点云吸收信息，再在少量 scene token 上做多层 self-attention。默认 M=768M=768M=768、token 维数为 128。MMM 是场景表示容量，增加到 256、512、768 时精度持续提高，但注意力成本和显存也随之增加。

点云流

确定性解码器通常在固定空间中查询 occupancy（判断空间位置是否在物体内部或者表面附近）或 SDF（有符号距离函数，判断到最近表面的距离）。场景范围会随相机覆盖改变，真实数据也经常缺少封闭网格和 SDF 真值，因此 NOVA3R 直接生成三维点坐标。

若强行比较第 nnn 个预测点和第 nnn 个真值点，损失会受点云排列影响；用 Chamfer Distance 虽然与排列无关，却需要大量最近邻搜索，也容易被点密度不均衡影响。NOVA3R 使用 flow matching 学习从数据点到噪声的连续速度场。

从真实点 x0∼Px_0\sim Px0​∼P 和均匀噪声 ϵ∼U(−1,1)3\epsilon\sim\mathcal{U}(-1,1)^3ϵ∼U(−1,1)3 构造直线路径：

xt=(1−t)x0+tϵ,t∈[0,1]x_t=(1-t)x_0+t\epsilon,\qquad t\in[0,1] xt​=(1−t)x0​+tϵ,t∈[0,1]

沿路径对 ttt 求导：

dxtdt=ϵ−x0\frac{dx_t}{dt}=\epsilon-x_0 dtdxt​​=ϵ−x0​

因此解码器只需预测常速度 ϵ−x0\epsilon-x_0ϵ−x0​：

LflowAE=Et,x0,ϵ[∥Φdec(xt,Z,t)−(ϵ−x0)∥22]\mathcal{L}_{\mathrm{flow}}^{\mathrm{AE}} =\mathbb{E}_{t,x_0,\epsilon} \left[ \left\| \Phi_{\mathrm{dec}}(x_t,Z,t)-(\epsilon-x_0) \right\|_2^2 \right] LflowAE​=Et,x0​,ϵ​[∥Φdec​(xt​,Z,t)−(ϵ−x0​)∥22​]

t=0t=0t=0 是真实点，t=1t=1t=1 是噪声。训练学习数据到噪声的正向速度；生成时从 t=1t=1t=1 的噪声出发，沿 ODE 反向积分回 t=0t=0t=0：

xt−Δt=xt−Δt Φdec(xt,Z,t)x_{t-\Delta t} =x_t-\Delta t\,\Phi_{\mathrm{dec}}(x_t,Z,t) xt−Δt​=xt​−ΔtΦdec​(xt​,Z,t)

对已知的一对 (x0,ϵ)(x_0,\epsilon)(x0​,ϵ)，条件速度确实恒为 ϵ−x0\epsilon-x_0ϵ−x0​；但推理时只给网络当前 xtx_txt​、时间 ttt 和场景 token ZZZ，它不知道这一个点最初来自哪个 x0x_0x0​。MSE 回归的最优解是所有可能路径速度的条件均值：

v∗(x,t∣Z)=E ⁣[epsilon−x0∣xt=x,Z]v^*(x,t\mid Z) =\mathbb{E}\!\left[epsilon-x_0\mid x_t=x,Z\right] v∗(x,t∣Z)=E[epsilon−x0​∣xt​=x,Z]

这个平均速度场满足概率流的连续性方程：

∂pt(x)∂t+∇x⋅(pt(x)v∗(x,t∣Z))=0\frac{\partial p_t(x)}{\partial t} +\nabla_x\cdot\left(p_t(x)v^*(x,t\mid Z)\right)=0 ∂t∂pt​(x)​+∇x​⋅(pt​(x)v∗(x,t∣Z))=0

直观上，它规定每个时刻某一小团概率质量应当向哪里移动。沿 ODE 积分时，不是在记忆训练点之间的一一匹配，而是在把整个噪声分布逐渐运输到场景表面分布。因此生成点可以没有固定顺序，也可以在推理时改变查询数量。

噪声使用 U(−1,1)3\mathcal{U}(-1,1)^3U(−1,1)3，与归一化后的场景立方体范围一致。ttt 接近 1 时，输入几乎是均匀噪声，网络主要依靠 ZZZ 判断场景大结构；ttt 接近 0 时，点已靠近表面，网络更多修正局部位置和密度。

论文把第一阶段称作 diffusion-based 3D autoencoder，但没有 KL 正则，scene token 也不被强制匹配高斯分布。随机性位于点查询和流解码过程，ZZZ 本身是确定性的场景编码。

联合解码

最简单的流解码可以逐点独立执行 cross-attention：每个噪声点只读取全局 token，不与其他点交流。计算很容易并行，但相邻点可能分别落到不同表面，局部结构也容易散乱。

NOVA3R 的 joint decoder 用三个步骤间接交换信息：

Z′=CrossAttn⁡(Z,xt),Z′′=SelfAttn⁡(Z′),xt′=CrossAttn⁡(xt,Z′′)\begin{aligned} Z'&=\operatorname{CrossAttn}(Z,x_t),\\ Z''&=\operatorname{SelfAttn}(Z'),\\ x_t'&=\operatorname{CrossAttn}(x_t,Z'') \end{aligned} Z′Z′′xt′​​=CrossAttn(Z,xt​),=SelfAttn(Z′),=CrossAttn(xt​,Z′′)​

先把噪声查询的信息汇入 MMM 个 scene token，在较小的 M×MM\times MM×M 注意力图中做全局混合，再把更新后的信息送回所有查询点。这样保留点间通信，又避免直接构造 N×NN\times NN×N 的大注意力矩阵。论文的解码器使用三个此类 Transformer block，实验中 joint decoder 的数值提升不算巨大，但细结构明显比独立解码整齐。

图像编码

第二阶段要解决的问题是：怎样让无位姿图像产生与第一阶段点云编码器相同语义的 ZZZ。

NOVA3R 以预训练 VGGT 为图像编码器。输入包含各视图的 patch token 和 MMM 个可学习 scene token：

Z^=Φtran ⁣(⋃i=1KtiI∪tS)\hat Z =\Phi_{\mathrm{tran}}\!\left( \bigcup_{i=1}^{K}t_i^I\cup t^S \right) Z^=Φtran​(i=1⋃K​tiI​∪tS)

scene token 被当作一个额外的“全局帧”，使用第一张图的 camera token，因此自然落在第一相机坐标系。它们与图像 token 一起经历 VGGT 的 frame-level 和 global-level attention，逐步汇集所有视图的几何信息。

第二阶段不再使用 VGGT 的深度头和 point-map 头。训练好的 Φdec\Phi_{\mathrm{dec}}Φdec​ 被冻结，只更新图像 Transformer 和初始 scene token：

LflowTran=Et,x0,ϵ[∥Φdec(xt,Z^,t)−(ϵ−x0)∥22]\mathcal{L}_{\mathrm{flow}}^{\mathrm{Tran}} =\mathbb{E}_{t,x_0,\epsilon} \left[ \left\| \Phi_{\mathrm{dec}}(x_t,\hat Z,t)-(\epsilon-x_0) \right\|_2^2 \right] LflowTran​=Et,x0​,ϵ​[​Φdec​(xt​,Z^,t)−(ϵ−x0​)​22​]

冻结解码器相当于固定一套“scene token 语言”。第一阶段规定什么样的 token 能解码成完整点云；第二阶段只学习把图像翻译成这种语言。它还能将无配对的三维点云数据用于第一阶段，将图像—三维配对数据留给第二阶段，降低数据准备难度。

“冻结解码器”并不意味着梯度无法穿过它。设图像编码器参数为 ψ\psiψ，Z^=Φtran,ψ(I)\hat Z=\Phi_{\mathrm{tran},\psi}(I)Z^=Φtran,ψ​(I)，则：

∇ψL=∂L∂Z^∂Z^∂ψ\nabla_{\psi}\mathcal{L} =\frac{\partial\mathcal{L}}{\partial\hat Z} \frac{\partial\hat Z}{\partial\psi} ∇ψ​L=∂Z^∂L​∂ψ∂Z^​

∂L/∂Z^\partial\mathcal{L}/\partial\hat Z∂L/∂Z^ 仍然由固定解码器反向计算，只是 Φdec\Phi_{\mathrm{dec}}Φdec​ 自身参数不更新。若 Z^\hat ZZ^ 缺少某面墙的信息，固定解码器会生成错误速度，误差便反传到图像 Transformer，迫使 scene token 学会补充相应场景信息。

实际模型采用 16 层 VGGT 变体，并从预训练权重初始化；DINOv2 图像 tokenizer 冻结。训练时默认 M=768M=768M=768 个 scene token、N=10 000N=10\,000N=10000 个目标点，两个阶段各训练 50 个 epoch。

分辨率

非像素对齐输出把点数从图像分辨率中解耦。推理时改变噪声查询数量 NNN，同一个 Z^\hat ZZ^ 可以生成不同密度的点云。论文附录展示了分辨率可调的结果，场景评估使用 100K 点，官方代码也允许通过 num_queries 指定查询数。

这里仍有实际约束：scene token 数固定为 768，决定全局表示的信息容量；联合解码还要让所有查询经由 scene token 交换信息，输出点数增加时计算和显存近似线性增长。它具备可变查询数的结构能力，但训练和主要实验集中在固定规模，极高分辨率下的细节不会无限增长。

评估指标

论文中的 Chamfer Distance 与 F-score（给定距离阈值 (\tau)。若预测点与某个真值点的距离小于 (\tau)，就认为该预测点正确） 分别回答“平均有多远”和“阈值内有多少点”。给定预测点集 PPP、真值点集 GGG 和距离阈值 τ\tauτ：

Precision⁡τ=1∣P∣∑p∈P1 ⁣[min⁡g∈G∥p−g∥2<τ]\operatorname{Precision}_{\tau} =\frac{1}{|P|} \sum_{p\in P} \mathbf{1}\!\left[\min_{g\in G}\|p-g\|_2<\tau\right] Precisionτ​=∣P∣1​p∈P∑​1[g∈Gmin​∥p−g∥2​<τ]

Recall⁡τ=1∣G∣∑g∈G1 ⁣[min⁡p∈P∥g−p∥2<τ]\operatorname{Recall}_{\tau} =\frac{1}{|G|} \sum_{g\in G} \mathbf{1}\!\left[\min_{p\in P}\|g-p\|_2<\tau\right] Recallτ​=∣G∣1​g∈G∑​1[p∈Pmin​∥g−p∥2​<τ]

Fτ=2Precision⁡τRecall⁡τPrecision⁡τ+Recall⁡τF_{\tau} =\frac{2\operatorname{Precision}_{\tau}\operatorname{Recall}_{\tau}} {\operatorname{Precision}_{\tau}+\operatorname{Recall}_{\tau}} Fτ​=Precisionτ​+Recallτ​2Precisionτ​Recallτ​​

Precision 低表示生成了很多离开真实表面的浮点，Recall 低表示真实表面有大量孔洞。τ\tauτ 越小，指标对细节和对齐越严格。论文还在括号中报告单向 G→PG\rightarrow PG→P 的 Chamfer 项，它只关心真值是否被覆盖，更直接反映场景补全能力，但不会惩罚额外生成的错误点，因此必须与双向 CD 或 F-score 一起看。

训练流程

实验结论

在 SCRREAM 单视图完整重建中，NOVA3R 的 complete CD 为 0.048，优于 VGGT 的 0.070；FS@0.05 从 VGGT 的 0.657 提高到 0.687。可见区域上 VGGT 的单向 CD 略优，符合两者目标差异：VGGT 更擅长紧贴观测表面，NOVA3R 把容量分配给全局均匀分布和遮挡补全。

Flow matching 的消融尤其关键。同一套第一阶段网络改用 Chamfer loss 后，SCRREAM 的 CD 从 0.011 变为 0.024，FS@0.02 从 0.904 降到 0.575；flow decoder 更慢，但对无序、密度变化明显的大场景稳定得多。输入分辨率由 2242224^22242 提升到 5182518^25182 也持续改善结果，因为图像 token 从 16216^2162 增至 37237^2372，scene token 得到了更细的视觉证据。

论文主要用一张或两张图训练，训练于两视图的模型还能直接泛化到四视图。NOVA3R 也可以把完整点云交给 TRELLIS 的后续阶段，进一步生成网格、3D Gaussian 或辐射场，说明非像素对齐点云可以作为通用三维中间表示。

方法特点

NOVA3R 的关键变化发生在输出坐标的“索引方式”。VGGT 用 (i,u,v)(i,u,v)(i,u,v) 索引三维点，点属于某张图的某个像素；NOVA3R 用集合索引 nnn，点只属于全局场景。去掉像素索引后，遮挡点获得了输出位置，重叠视图也不再强制产生重复点。

两阶段训练则解决了全局表示难以直接学习的问题。第一阶段用完整点云建立一套可解码的 scene-token 空间，第二阶段把图像映射进这套空间。它类似先训练一种三维“语言”，再训练视觉翻译器；固定 decoder 保证图像 token 必须携带足够的完整几何信息，不能依赖一个同步变化的 decoder 绕过表示瓶颈。

Flow matching 同时承担生成先验与无序集合解码。它比逐点回归更适合多解的隐藏结构，也比直接 Chamfer 优化提供更平滑的分布级训练信号。不过 NOVA3R 生成的仍是点分布，表面拓扑并未显式编码，这正是 VolFill 进一步引入 TUDF 的原因。

局限

  • 遮挡区域由数据先验补全，单张图可能对应多个合理场景，论文输出其中一种，无法保证与真实隐藏结构一致；
  • 完整点云监督由稠密深度聚合近似时，本身可能含孔洞、位姿误差和重复点；
  • 默认 768 个 scene token 对大场景仍是有限瓶颈，复杂结构可能被平滑或遗漏；
  • 点云是无结构采样，直接查询 occupancy、碰撞或提取闭合网格并不方便，Poisson 重建可能产生碎片；
  • 训练视图最多约两张，超多视图和动态场景不在主要训练范围内；
  • flow decoder 需要多步 ODE 积分，速度低于一次回归的 VGGT。

NOVA3R 解决了“逐像素几何缺少遮挡面、跨视图重复”的问题，但无结构点云又带来曲面提取困难。VolFill 接着把生成目标从点集合换成三维距离场。
