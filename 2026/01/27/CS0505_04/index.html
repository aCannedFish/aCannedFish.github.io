数据结构-04：树

发表于2026-01-27|更新于2026-06-22|Note(Data Structure)
|浏览量:

树的抽象类

树是一种递归结构：一个结点可以有若干子树，而每棵子树本身又是一棵树。和线性表相比，树不再只有唯一的前驱/后继关系，而是体现层次关系，例如文件目录、组织结构、表达式语法树等。抽象类中的 root、parent、child 等接口描述的是这种层次关系，而不是具体采用数组还是指针存储。

二叉树

二叉树是最常用的树形结构之一，因为每个结点最多只有左、右两个孩子，递归定义简单，代码实现也相对规整。后续的二叉查找树、堆、哈夫曼树等结构，都可以看作在二叉树上额外增加不同约束：查找树增加有序性，堆增加父子优先级关系，哈夫曼树增加带权路径长度最小化目标。

基本定义

  1. 二叉树（Binary Tree）是结点的有限集合，它或者为空，或者由一个根结点及两棵互不相交的左、右子树构成，而其左、右子树又都是二叉树。
  2. 注意：二叉树必须严格区分左右子树。即使只有一棵子树，也要说明它是左子树还是右子树。交换一棵二叉树的左右子树后得到的是另一棵二叉树。
  3. 二叉树和有序树是不同的概念。
  4. 树和二叉树都是树型结构。二叉树不是一种特殊的树。二叉树可以为空。树不能为空。

满二叉树

  • 一棵高度为 kkk 并具有 2k−12^k - 12k−1 个结点的二叉树称为满二叉树。
  • 一棵二叉树中任意一层的结点个数都达到了最大值。

满二叉树强调“每一层都填满”，因此结点数和高度之间有非常紧的关系。只要知道高度，就能直接推出结点总数；反过来也能通过结点数判断高度。这类结构常作为复杂度分析中的理想情况。

完全二叉树

在满二叉树的基础上，最后一层的结点可以不满，但必须从左到右依次排列。

  • 所有叶结点都出现在最低的两层上。
  • 对任意结点，如果其右子树高度为 kkk，则其左子树高度为 kkk 或 k+1k + 1k+1。

完全二叉树强调“除了最后一层外尽量填满，最后一层从左向右填”。这个性质使它可以用数组紧凑存储，并通过下标直接推导父子关系，因此二叉堆会要求底层树形必须是完全二叉树。

二叉树性质

  1. 一棵非空二叉树的第 iii 层上最多有 2i−12^{i - 1}2i−1 个结点（i≥1i \ge 1i≥1）。
  2. 一棵高度为 kkk 的二叉树最多有 2k−12^k - 12k−1 个结点。
  3. 对于一棵非空二叉树，如果叶子结点数为 n0n_0n0​，度数（子结点的个数）为 222 的结点数为 n2n_2n2​，则有：

n0=n2+1n_0 = n_2 + 1 n0​=n2​+1

  1. 结论推广：对于一棵非空 KKK 叉树，如果叶子结点数为 n0n_0n0​，度数为 iii 的结点数为 nin_ini​，则有：

n0=1+∑i=2K(i−1)nin_0 = 1 + \sum_{i = 2}^{K}(i - 1)n_i n0​=1+i=2∑K​(i−1)ni​

  1. 具有 nnn 个结点的完全二叉树的高度：

k=⌊log⁡2n⌋+1k = \lfloor \log_2 n \rfloor + 1 k=⌊log2​n⌋+1

二叉树的遍历

  1. 前序遍历

如果二叉树为空，则操作为空，否则：

  • 访问根结点
  • 前序遍历左子树
  • 前序遍历右子树
  1. 中序遍历

如果二叉树为空，则操作为空，否则：

  • 中序遍历左子树
  • 访问根结点
  • 中序遍历右子树
  1. 后序遍历

如果二叉树为空，则操作为空，否则：

  • 后序遍历左子树
  • 后序遍历右子树
  • 访问根结点

Tip:根据前序序列+ 中序序列可以唯一确定一棵二叉树。根据后序序列+ 中序序列也可以唯一确定一棵二叉树。

三种深度优先遍历的差别只在“访问根结点”的时机：前序是先访问根，中序是夹在左、右子树之间，后序是最后访问根。写代码时递归框架几乎完全一致，真正改变的只有 cout << t->data 放在哪一行。层次遍历则完全不同，它不是沿着一条路径深入，而是借助队列按一层一层的顺序访问。

二叉树的类定义

这一段类定义里同时出现了“公有包裹函数”和“私有递归函数”。例如 preOrder() const 是给外部调用的接口，真正递归的是 preOrder(Node *t) const。这样设计的好处是：外部调用者不需要知道根指针 root 的存在，只需要调用无参遍历函数；类内部则把当前子树根 t 作为递归状态不断向下传递。

层次构建二叉树

createTree 使用队列，是因为它按层次顺序构造树。每读入一个非空结点，就把它入队；之后从队列中取出一个结点，再询问它的左右孩子。这样可以保证输入顺序与树的层序结构一致。flag 是空结点标记，作用类似“这里没有孩子”，从而避免为不存在的子树继续入队。

二叉树遍历的非递归实现

  • 递归是程序设计中强有力的工具。
  • 递归程序结构清晰、明了、美观。
  • 递归程序的弱点：它的时间、空间的效率比较低。
  • 所以在实际使用中，我们常常希望使用它的非递归版本。二叉树的遍历也是如此。尽管二叉树遍历的递归函数非常简洁，但有时我们还是希望使用速度更快的非递归函数。

非递归前序遍历

  • 前序遍历第一个被访问的结点是根结点，然后访问左子树，最后访问右子树。
  • 可以设置一个栈，保存将要访问的树的树根。
  • 开始时，把二叉树的根结点存入栈中。然后重复以下过程，直到栈为空：
  • 从栈中取出一个结点，输出根结点的值；
  • 然后把右子树，左子树放入栈中。

前序非递归版本的关键是栈的后进先出特性。因为希望左孩子先被访问，所以入栈时必须先压右孩子、再压左孩子；下一轮弹出时左孩子才会先出来。这里栈中保存的是“接下来还没有访问、但已经被发现的子树根”。

非递归中序遍历

  • 采用一个栈存放要遍历的树的树根。
  • 中序遍历中，先要遍历左子树，接下去才能访问根结点，因此，当根结点出栈时，我们不能访问它，而要访问它的左子树，此时要把树根结点暂存一下。
  • 由于左子树访问完后还要访问根结点，因此仍可以把它存在栈中，接着左子树也进栈。此时执行出栈操作，出栈的是左子树。左子树问结束后，再次出栈的是根结点，此时根结点可被访问。根结点访问后，访问右子树，则将右子树进栈。

TimesPop 可以理解为“这个结点已经从栈中弹出过几次”。中序遍历中，一个结点第一次弹出时还不能访问，因为它的左子树还没处理；第二次弹出时，左子树已经处理完，才访问根结点，并转向右子树。这个技巧本质上是在用显式状态模拟递归调用栈。

非递归后序遍历

  • 将中序遍历的非递归实现的思想进一步延伸，可以得到后序遍历的非递归实现。
  • 当以后序遍历一棵二叉树时，先将树根进栈，表示要遍历这棵树。
  • 根结点第一次出栈时，根结点不能访问，应该访问左子树。于是，根结点重新入栈，并将左子树也入栈。
  • 根结点第二次出栈时，根结点还是不能访问，要先访问右子树。于是，根结点再次入栈，右子树也入栈。
  • 当根结点第三次出栈时，表示右子树遍历结束，此时，根结点才能被访问。

后序遍历最容易混乱，因为根结点必须等左、右子树都访问完之后才能输出。因此一个结点需要经历三种状态：第一次弹出表示准备处理左子树，第二次弹出表示左子树已完成、准备处理右子树，第三次弹出表示左右子树都已完成、可以访问根结点。TimesPop 记录的正是这个阶段。

哈夫曼树与哈夫曼编码

哈夫曼编码解决的是“如何给高频字符更短编码、低频字符更长编码，并且仍能唯一解码”的问题。若所有字符都使用固定长度编码，简单但可能浪费空间；若允许变长编码，就必须保证一个字符的编码不能成为另一个字符编码的前缀，否则解码时会产生歧义。

因此哈夫曼树同时包含两个目标：编码必须是前缀码，平均编码长度还要尽可能短。树中从根到叶子的左右路径可以分别记为 0 和 1，某个字符所在叶子的路径就是它的编码。

前缀编码与哈夫曼树

  • 字符只放在叶结点中。
  • 字符编码可以有不同长度。
  • 每个字符的编码都不可能是其他字符编码的前缀
  • 前缀编码可被惟一解码
  • 哈夫曼树是一棵最小代价的二叉树，所有的字符都包含在叶结点上。

“字符只放在叶结点”是前缀编码成立的关键。如果某个字符放在内部结点，那么它的编码就会成为其子树中所有字符编码的前缀，解码时读到这段比特后就无法判断应该停下还是继续读。

哈夫曼算法

  1. 给定一个具有 n 个权值的结点的集合 A。
  2. 执行 n - 1 次循环,在每次循环时执行以下操作:从当前集合中选取权值最小、次最小的两个结点，以这两个结点作为内部结点 bi 的左右儿子，bi 的权值为其左右儿子权值之和。
  3. 在集合中去除这两个权值最小、次最小的结点，并将内部结点 bI 加入其中。这样，在集合 A 中，结点个数便减少了一个。这样，在经过了 n-1 次循环之后，集合 A 中只剩下了一个结点，这个结点就是根结点。

哈夫曼算法的贪心直觉是：权值越小的字符越应该出现在越深的位置，因为深层路径会带来更长编码。每次合并两个最小权值结点，相当于先确定“最不常出现的两个字符应该成为兄弟”，它们共同承担一段较长的前缀。不断合并后，根到叶子的路径就自然形成了每个字符的编码。

哈夫曼树的存储

  1. 在哈夫曼树中，每个要编码的元素是一个叶结点，其它结点都是度数为 2 的节点。
  2. 一旦给定了要编码的元素个数，由 n0=n2+1n_0 = n_2 + 1n0​=n2​+1 可知哈夫曼树的大小为 2n−12n - 12n−1。
  3. 哈夫曼树可以用一个大小为 2n 的数组来存储。0位置不用，根存放在下标 1 位置。叶结点依次放在 n+1 到 2n 的位置。
  4. 每个数组元素保存的信息：结点的数据、权值和父结点和左右孩子的位置。
  5. 数组下标的意义：这里的数组只是“顺序表容器”，不是完全二叉树的层序存储。因此不能使用 2i、2i + 1、i / 2 推导父子关系；父结点、左孩子、右孩子都由结点中的 parent、left、right 字段显式记录。
