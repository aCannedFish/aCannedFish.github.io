计算机系统工程-01：系统扩展

发表于2026-09-24|更新于2026-10-06|Note计算机系统工程
|浏览量:

规模增长

数据变多、计算量增加、用户请求增多时，存储和计算系统也要扩展。语言模型就是一个例子：它接收一串 token，计算下一个 token 的分数，再选出或采样一个 token 继续生成。这里的 token 是文本经过编码后的基本单位，分数称为 logits。

课件先介绍编程助手、客户服务等应用，再讨论支撑这些应用的计算、数据和存储。

课件用每天增长 1% 的例子说明累积效应：1.01365≈37.81.01^{365}\approx37.81.01365≈37.8。要在计算系统中获得持续增长的收益，算法也得能用好增加的资源。

搜索和学习

Rich Sutton 在《苦涩的教训》中总结，长期来看，能持续利用计算资源的方法往往更有效。搜索和学习是课件的两个主要例子。具体任务能提高多少，仍取决于算法、数据和训练方式。

程序员设计搜索或学习过程，让程序从计算和反馈中找出具体策略。系统负责保存数据、执行计算、传递结果，并处理运行中的故障。

棋类搜索

棋类程序包含评估函数和搜索。评估函数 f(s)f(s)f(s) 给未结束局面打分，搜索展开未来着法。Minimax 假设己方选最大收益、对手选最小收益；alpha-beta 剪枝根据已知上下界跳过不会改变选择的分支。

图中白方在根节点取最大值，黑方在下一层取最小值。左分支叶子 3、5、6 给出最坏结果 3；中间 6、7、4 给出 4。右分支先发现 1，最终最小值不可能高于 1，因此白方已有 4 时无需继续看右侧 9、2。根最终选择中间分支。

Deep Blue 在 1997 年击败 Kasparov，课件强调了深度搜索、专用硬件和并行计算。往后多看几步，程序有机会发现当前走法的后果。搜索树也会变大，剪枝和并行计算用来控制这部分成本。

围棋自博弈

课件给出围棋约 2×101702\times10^{170}2×10170 个合法局面、国际象棋约 104710^{47}1047 个的量级，并比较约 250 与 35 的候选着法数。围棋搜索空间更大，直接穷举难以实行；AlphaGo 结合搜索与学得的策略和局面评估，引导探索方向。

横轴是训练时间，纵轴是衡量棋力的 Elo 分数。紫线利用人类棋谱训练，起点较高。蓝线从较弱水平开始自博弈，在这次实验中继续提高，超过紫线和 AlphaGo Lee 的虚线。程序通过对局结果获得反馈，再调整下次的选择。

图像特征

SIFT 由人设计关键点、尺度、方向和描述子规则；CNN 在规定网络结构后训练滤波器等权重。两者都需要方法设计，区别在于哪些表示可随训练调整。

上方先找关键点、确定方向、计算特征，再汇集特征并训练分类器。图中的特征提取规则由人预先确定。下方的 CNN 用多层计算提取特征，把预测结果与 cat 标签比较，再沿蓝色箭头调整网络参数。

这些滤波器能识别不同方向的边缘和颜色变化，参数通过训练得到，网络结构和训练条件由开发者选择。2012 年 ImageNet 比赛中，AlexNet 的 top-5 错误率为 15.3%，第二名为 26.2%。top-5 错误率指模型给出的前五个候选类别都未命中正确类别的比例。

算力和数据

单位计算成本长期下降，使更多搜索与学习成为可能。单芯片仍受功耗、散热和制造约束，多芯片、多机能扩大总计算量，但通信、调度和故障会增加系统工作。

互联网和代码仓库积累了大量文本，为语言模型提供了训练数据。存储系统保存这些内容，让训练程序反复读取；计算设备和网络则负责处理并传递数据。

训练计算量

课件用简化公式估算一批 Transformer 训练的计算量：

F≈6BWSF\approx6BWS F≈6BWS

B 表示这一步处理多少条序列，W 表示模型参数量，S 表示每条序列的平均 token 数。前向计算中，每个权重对一个 token 做一次乘法和一次加法，约计两次浮点操作。反向计算输入和权重的梯度约再需四次，合起来得到系数 6。这是近似估算，注意力计算和优化器更新等还会增加开销。

BSBSBS 是这一步处理的 token 数。把所有训练步的 token 数相加，才得到总训练数据量。模型可以增加参数、读取更多训练数据，或处理更长的上下文；这些变化都会增加计算和存储需求。

课件用几组配图介绍这些方向，并引用 Chain-of-Thought 的例子，说明较长文本可以容纳中间推理步骤。实际收益需要通过任务测试来衡量。

若 B=128B=128B=128、S=2048S=2048S=2048、W=109W=10^9W=109，这一步约需 1.57×10151.57\times10^{15}1.57×1015 次浮点操作。估算运行时间时，还要知道设备每秒能完成多少操作，以及读取数据和通信花费的时间。

缩放定律

三幅图横轴分别为计算量、数据集 token 数和参数量，纵轴为测试损失。在所示范围的对数坐标里，趋势近似直线，因而可用幂律拟合；浅色训练轨迹还表明，同一预算下配置不同，结果也不同。

Chinchilla 进一步研究固定训练预算如何分配参数 N 和数据 D，课件给出拟合：

L^(N,D)=E+ANα+BDβ\hat L(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta} L^(N,D)=E+NαA​+DβB​

E 是公式中与 N、D 无关的常数项。E、A、B 等系数由实验拟合得到。这里的 B 是拟合系数，前文的 B 表示批次大小，阅读时要按所在公式区分。

每条曲线对应一个固定计算预算。模型较小时，增加参数能降低损失。继续增加参数，会减少同一预算下可处理的训练数据，损失可能回升。曲线最低点表示这次实验中较合适的参数和数据配比。

右侧两图分别给出不同预算下较合适的参数量和 token 数。在这项研究的训练条件下，两者都接近按计算量的平方根增长。预算增加时，需要一起增加参数和训练数据。实际选模型大小时，还要考虑推理成本、数据质量和网络结构。

应用和存储

课件设想同时支持社交、交易和模型服务的应用。LAMP 中 Linux 管理系统资源，Apache 一类服务器处理 Web 请求，MySQL 与文件系统保存表和文件，PHP 等业务层生成响应。

应用通过文件路径、键值和表访问数据。文件系统记录 chat.log 的名字、大小和数据块位置，数据库处理表和查询。应用调用这些接口后，由相应系统完成底层读写。

存储扩展

课件引用 Facebook 2010 年的上传量：每周约十亿张照片，产生约 60 TB 新数据，平均每天约 8.6 TB。按 40 TB 存储容量估算，约 40/8.6=4.740/8.6=4.740/8.6=4.7 天装满；若数据保留三份，约 40/(3×8.6)=1.640/(3\times8.6)=1.640/(3×8.6)=1.6 天就用完容量。

分布式存储把多个磁盘接入网络，应用通过 RPC 使用统一接口；增加磁盘或阵列可扩容量。课件逐帧展示从本机一块盘到远端阵列再增加阵列，随之要回答每条数据在哪个节点，以及扩容时怎样迁移。

延迟和缓存

延迟是一次请求从发送到收到回复的时间，吞吐量是每秒完成的请求数或数据量。远端读取要经过网络传输、服务器排队、磁盘读取和回复传输。增加机器可以分担请求，减少排队；网络传播时间还受距离影响。

图中的示例值包括：内存访问约 100 ns，SSD 随机读 4 KB 约 150 μs，同一数据中心的网络往返约 500 μs，磁盘寻道约 10 ms。150 μs 等于 150000 ns，能看出这些操作的时间差距。图中数字来自不同年代和条件，分析自己的程序时需要实际测量。

缓存把常用数据放到速度更快的位置。如果少量数据承担了大部分访问，小容量缓存也能减少很多等待。是否有效，可以通过命中率和请求耗时来测量。

缓存更新

B 先查询 X，得到“文件不存在”，并把这个结果存入缓存。A 随后写入 X。B 再次查询时直接返回缓存中的 X:none，因此仍看不到新文件。系统可以在写入时通知 B 清除旧缓存，也可以让 B 定期检查修改时间或版本。TTL 是缓存的有效时长，超过这个时间后要重新查询。采用这些办法时，需要说明更新后多久能读到新内容。

一致性模型说明多次读写可以出现什么结果。最终一致性允许副本暂时不同，更新停止且通信恢复后，各副本最终一致。因果一致性要求有前后依赖的操作按同一顺序被看到。顺序一致性要求所有操作能排成一个共同顺序，并保留各进程的执行顺序。线性一致性还要保留实际时间上的先后关系。图中的 strict 表示更严格的理想时间要求。

为了满足更多顺序要求，节点通常需要交换更多消息。选择哪种模型，要看业务能接受哪些读取结果和等待时间。

机器故障

课件假设单台机器平均约一万天故障一次。一万台机器组成集群后，长期平均每天约发生一次机器故障；某天可能没有故障，也可能多台同时出问题。原因包括配置错误、软件 bug、内存泄漏、硬件损坏、网络和电力故障。

写入和恢复

持久性说明成功写入的数据在系统规定的故障情况下能继续保存。原子性说明一组更新要么全部完成，要么全部撤销。系统需要分别说明能承受哪些故障，以及哪些操作共同完成。

图中只写入了一部分新数据，应用读到一半新、一半旧的内容。如果需要整份文件同时更新，系统要安排日志、写时复制或其他保存流程，在恢复时选出完整旧版本或新版本。

原本 A=100、B=0。B 加上 100 后，A 的扣款还没完成，机器就崩溃了，随后读到 A+B=200。转账需要把两次修改放在同一事务中，并在故障恢复时一起完成或撤销。

服务和副本

假设在同一时间窗口内，每个副本不可用的概率都是 p，且 k 个副本的故障相互独立，那么它们同时不可用的概率为 pkp^kpk。p=10−3p=10^{-3}p=10−3、k=3k=3k=3 时为 10−910^{-9}10−9。这个计算依赖故障相互独立的假设。实际部署时，常把副本放在不同机架，使用不同的电源，减少它们同时故障的机会。

按图中的统计，60 天内异常时间约为 60×24×(1−0.9929)=10.22460\times24\times(1-0.9929)=10.22460×24×(1−0.9929)=10.224 小时。顶部状态表示当前运行情况，下方历史条记录过去 60 天的情况。

应对故障的常见做法包括保存多份数据，以及在请求失败后重试。数据副本分布在不同机器上，一台机器失效后，其他机器可以继续服务。系统还要协调副本更新，并决定主节点失效后由谁接替。

Raft 和 Paxos 用来协调节点对状态变化的意见，并处理主节点选择。后续课程会介绍这些协议。

并行计算

一个线程等待 I/O 时，其他线程可以继续处理请求。增加机器也能同时处理更多任务。如果它们共用的网络或存储已经忙满，继续加机器的收益就会减小。

AAA 分为 A0,A1,A2A_0,A_1,A_2A0​,A1​,A2​，三个计算单元读取同一个 x，分别写入 y0,y1,y2y_0,y_1,y_2y0​,y1​,y2​。串行计算约需 3T；并行计算约需 T，再加上分配任务和收集结果的时间。三台机器仍各做约 T 的计算，加速来自同时执行。

模型并行

layer 1 把计算结果传给 layer 2，layer 2 再传给 layer 3。处理一批数据时，图中很多时间都在等待，这些空闲时段称为流水线气泡。交错处理多个小批次可以减少等待，调度时仍要安排好各层的数据依赖。

一个训练步先做前向传播，再计算梯度，最后更新参数。反向传播要用前向结果，更新要等梯度完成。满足这些条件后，独立的子任务可以同时执行。

图中每块 GPU 都能运行完整模型。每个请求依次经过三层，耗时约 3T；三块 GPU 在这段时间内完成三个请求，4、5、6 还在排队。实际能处理多少请求，还取决于模型大小、内存和其他开销。

并发读写

T1 和 T2 都先读到 left=1。T1 把库存写成 0，建立 Alice 的订单；T2 也根据刚才读到的 1，把库存写成 0，建立 Bob 的订单。于是只有一张票，两人却都下单成功。按顺序处理时，第二个人会看到库存已经为 0，购买就会停止。为保证这一结果，系统需要把查询库存、判断余票、扣票和建立订单一起协调。

隔离性用于控制事务之间的相互影响。系统可以用两阶段锁（2PL）或乐观并发控制（OCC）处理冲突。上面的购票例子希望得到与串行执行相同的结果；使用数据库时，还要查看所选隔离级别提供的保证。

例如，两个人都请求“购买任意一张票”，开始时还没选定具体票号。如果后来选中了同一张票，系统就要协调这两次购买。为此，需要记录每个事务访问了哪些数据。

两个 GPU 都读到 w=1w=1w=1，各自算出更新量 Δw=−1.2\Delta w=-1.2Δw=−1.2。同步训练先把两份更新取平均，再执行一次，得到 w=−0.2w=-0.2w=−0.2。异步训练收到第一份更新后得到 -0.2，收到第二份后继续加上 -1.2，得到 -1.4。第二份更新是根据旧的 w=1w=1w=1 算出的。图中的损失为 w2w^2w2，从 -0.2 变成 -1.4 会让损失增大。同步训练需要等待较慢的工作节点；异步训练则需要控制旧参数算出的更新对结果的影响。

横轴是 worker 数，蓝线是同步训练，绿线是异步训练。在这次实验中，蓝线的测试精度更高；worker 较多时，绿线达到收敛所需的训练量也更大。比较训练总时间，还要结合每步耗时。

扩展限制

系统扩展会受到芯片算力、功耗、网络延迟和带宽限制。CAP 定理讨论网络分区时的读写服务：如果节点间无法通信，系统要在保持线性一致性和继续回答所有未故障节点的请求之间作选择。实际服务还要规定请求最多等待多久。

后续课程会继续讨论事务、故障恢复、副本协调、安全和网络。系统规模增加后，仍要保证读写结果正确，故障后能恢复数据，并满足请求的完成时间和处理量要求。
