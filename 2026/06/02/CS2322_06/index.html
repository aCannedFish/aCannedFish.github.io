高级数据结构-06：中位数与众数

|浏览量:

众数

众数的定义

给定一个包含 nnn 个元素的无序向量或数组，如果其中存在某个元素，其出现的总次数严格大于向量总长度的一半（即出现次数 >⌊n/2⌋> \lfloor n/2 \rfloor>⌊n/2⌋），则该元素被正式定义为这个向量的“众数”。这种严格定义与统计学中通常意义上的“出现频率最高的数”（即频繁数 Mode）有所不同。为了明确这一概念，我们可以考察以下两个具体实例：

  • 在序列 {3, 5, 2, 3, 3} 中，总长度为 5。元素 3 出现了 3 次。因为出现次数 3>⌊5/2⌋=23 > \lfloor 5/2 \rfloor = 23>⌊5/2⌋=2，所以 3 是该序列的众数。
  • 在序列 {3, 5, 2, 3, 3, 0} 中，总长度增加到了 6。元素 3 依然只出现了 3 次。根据严格定义，由于 333 并不严格大于 6/2=36/2 = 36/2=3，因此在这个特定的向量中，根本不存在任何众数。

面对这个问题，有以下两种“平凡算法”：

  1. 全量排序结合线性扫描：既然目标是寻找出现次数极多的元素，直观操作是将无序元素重新排列。如果使用快速排序或归并排序对整个数组进行升序排列，所有相同的元素必定会在数组中连续相邻。此时，只需再进行一次时间复杂度为 O(n)\mathcal{O}(n)O(n) 的线性扫描，记录连续相同元素的个数，一旦发现某个元素的计数超过了 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ 即可立刻返回。这种方法的算法瓶颈在于排序阶段，其时间复杂度为 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)，空间复杂度取决于所选用的排序算法（如归并排序需要 O(n)\mathcal{O}(n)O(n) 的辅助空间，快速排序需要 O(log⁡n)\mathcal{O}(\log n)O(logn) 的递归栈空间）。从必要性条件来看，如果一个序列存在众数，那么在对其进行完整排序之后，该众数必定覆盖数组的中间位置。这意味着，众数如果存在，它必然同时也是该序列的中位数。在学术界早期的探索中，寻找众数的过程往往依赖于寻找中位数的算法。

  2. 散列表统计法：另一种典型的“空间换时间”策略是利用散列表数据结构。遍历整个数组，将每个元素作为键（Key），将其出现的次数作为值（Value）存储在散列表中。如果某个元素的计数值在累加过程中超过了阈值 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋，则宣告找到了众数。这种方法得益于散列表 O(1)\mathcal{O}(1)O(1) 的平摊查找时间，能够将整体时间复杂度降至线性 O(n)\mathcal{O}(n)O(n)。然而，这种性能提升以额外空间为代价。在最坏情况下（例如数组中绝大多数元素都各不相同），散列表需要额外的 O(n)\mathcal{O}(n)O(n) 级别内存空间来存储键值对信息。

能否设计出一种算法，其执行时间严格不超过线性边界 O(n)\mathcal{O}(n)O(n)，且运行过程中所需的附加内存空间严格不超过常数级别 O(1)\mathcal{O}(1)O(1)？

Boyer-Moore 多数投票算法

Boyer-Moore 算法的核心思想可以概括为“减而治之”以及“异类相消”策略。该算法能够在仅需常数级别内存（几个标量变量）以及单次线性时间遍历的前提下，找出一个序列中潜在的众数候选者。算法的运行状态机很精简，只需在内存中维护两个局部状态变量：

  • majority_candidate：用于记录当前轮次可能成为众数的候选元素。
  • counter：用于记录该候选元素相对其他元素的抵消余量，初始值设为 0。

算法从前向后逐一处理序列中的每一个元素 xxx，其内部逻辑表现为少量分支判断：

  1. 重置阶段：当读取到一个新元素 xxx 时，如果此时计数器 counter 恰好为 0，说明之前的候选者已经被其他元素抵消。算法将当前元素 xxx 设为新的 majority_candidate，并将 counter 设置为 1。
  2. 抵消阶段：如果此时 counter 并不为 0，说明当前已有候选者。算法会将新读取的元素 xxx 与当前的 majority_candidate 展开比对：
  • 如果它们是相同的元素，说明当前候选者得到一次额外计数，counter 递增 1。
  • 如果它们不相同，说明当前元素与候选者互相抵消一次，counter 递减 1。

当整个数组的所有元素都被处理完毕后，最后保留在 majority_candidate 变量中的元素，就是整个序列的众数候选者。若题目不保证众数存在，还需要再扫描一次验证其出现次数是否超过阈值。

counter 可以理解为当前候选者在尚未被抵消的片段中的净票数，而不是它在全数组中的真实出现次数。每遇到一个不同元素，就相当于拿一个候选者和一个非候选者配对删除。若某个元素真的超过一半，那么无论怎样配对删除，它总会在剩余序列中留下至少一个代表。

假设输入数组为 1, 2, 3, 2, 2, 2, 4, 2, 2（共 9 个元素，其中 2 出现了 6 次，因此是众数）。

减而治之的第二遍扫描

如果在遍历过程中的某一个特定时刻 ttt，计数器 counter 恰好被减为了 0，这意味着什么？这表明，在刚刚被扫描过的一个长度必定为偶数的前缀子序列 PPP 中，被选定为阶段候选者的元素与其余所有不等于该候选者的元素，在数量上实现了 1:1 抵消。

此时，整个原序列向量 AAA 就在逻辑上被切割成了两半：前缀 PPP 和剩余的后缀序列 A−PA - PA−P。根据众数的数学定义，如果原序列 AAA 中确实隐藏着一位众数 mmm，那么：

  1. 由于在刚刚被剔除的前缀 PPP 中，所有元素都完成了两两抵消，mmm 在这个局部群体 PPP 中所占据的比例最多只能是正好一半（即它作为候选人被其他元素全部抵消掉，或者它作为非候选元素抵消其他候选元素）。

  2. 这就引出了一个关键推论：既然 mmm 在全局中占据多数（超过一半），而在抛弃的前缀 PPP 中最多只占据一半，那么在剩下的后缀序列 A−PA - PA−P 中，mmm 仍然保持多数地位。

  3. 换句话说，向量 AAA 拥有众数，当且仅当在其剥离掉前缀 PPP 之后的后缀 A−PA - PA−P 中，也拥有完全相同的众数 mmm。

通过这种方式，算法持续将能够互相抵消的前缀剥离，从而缩小问题的考察规模。majCandidate 函数通过 c == 0 判断当前前缀是否抵消完毕，并在随后的扫描中动态调整 majCandidate 的指向。

然而，算法还有一个需要注意的边界。Boyer-Moore 算法的第一遍扫描只提供关于众数存在的“必要条件”：它在数学上只能保证，假如这个序列确实存在一个众数，那么这个众数必定是最终残留在候选变量里的元素。但是，如果序列本身没有众数，例如 1, 2, 3, 4, 5 中每个元素都只出现一次，算法依然会执行抵消逻辑，并在最后留下一个任意幸存者（比如在这个例子中可能是 5）。这个幸存者不是众数，因为整个数组没有众数。如果仅执行一遍算法而不验证，算法可能返回一个并不满足众数定义的候选元素。

因此，除非问题域已经保证输入序列中一定存在众数，否则必须对数组发起第二遍独立扫描。第二遍扫描的目的，是统计第一遍得到的候选元素在原数组中实际出现了多少次。只有当它的出现次数严格大于 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ 时，才能确认其众数地位并将其输出；否则应通过返回空值或抛出异常来表明该序列不存在众数。

中位数

在长度为 nnn 的有序序列 SSS 中，若采用从 0 开始的下标，本文将元素 S[⌊n/2⌋]S[\lfloor n/2 \rfloor]S[⌊n/2⌋] 作为中位数；当 nnn 为偶数时，这对应上中位数。事实上，正如前文所提及的，寻找中位数本质上是寻找第 kkk 大元素（k-selection 问题）的一个特例。

先来解决一个在归并排序框架下常见的衍生子问题：假设存在两个已经各自完全排序的数组，如何高效找出它们合并后的全局中位数？

蛮力归并与及其优化

假设系统任意给定了两个有序向量 S1S_1S1​ 和 S2S_2S2​，它们的长度分别为 n1n_1n1​ 和 n2n_2n2​。

最直观的蛮力算法是：直接把两个有序数组按顺序合并成一个新的全局有序数组 SSS。合并完成之后，直接根据数组索引，取位于 S[(n1+n2)/2]S[(n_1 + n_2)/2]S[(n1​+n2​)/2] 附近的中间元素即可。这种做法需要依次访问并搬运每一个元素到新的内存空间中，时间复杂度为 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​)，同时需要额外开辟 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​) 的连续空间来存放临时数组，因此不适合处理大规模数据。

二分查找与分治法

能否突破线性的枷锁，找到一种对数级别 O(log⁡(n1+n2))\mathcal{O}(\log(n_1+n_2))O(log(n1​+n2​)) 的算法？它的最优解法，必然要求我们充分利用两个数组已经有序这一信息，从而利用分治策略。

首先考察最为理想的等长子向量情况（即假设 S1S_1S1​ 和 S2S_2S2​ 的长度一致，均为 nnn）。此时，我们不再像双指针法那样慢吞吞地从头开始比较，而是直接提取出两个数组各自内部的中位数进行比对：令 m1=S1[⌊n/2⌋]m_1 = S_1[\lfloor n/2 \rfloor]m1​=S1​[⌊n/2⌋]，同时令 m2=S2[⌊(n−1)/2⌋]m_2 = S_2[\lfloor (n-1)/2 \rfloor]m2​=S2​[⌊(n−1)/2⌋]。其结果会引发三种分支：

  1. 若 m1=m2m_1 = m_2m1​=m2​，由于这两个局部中位数相等，并且各自刚好大于原来数组中一半的成员，它们顺理成章地不仅是各自数组的中位数，也必然是合并后数组的全局中位数。算法至此结束，直接将该值返回。
  2. 若 m1<m2m_1 < m_2m1​<m2​，S1S_1S1​ 的前半部分（即所有严格小于等于 m1m_1m1​ 的底层元素）在合并后的数组中只能位于较靠前的位置，不可能成为全局中位数。同理，S2S_2S2​ 的后半部分必定位于全局序列的较靠后位置，同样不可能成为中位数。基于这一事实，可以将 S1S_1S1​ 的前半部分和 S2S_2S2​ 的后半部分直接排除在搜索范围之外。由于截断过程中，极小元素集合与极大元素集合的数量保持平衡，中位数的目标秩不会发生偏移。
  3. 若 m1>m2m_1 > m_2m1​>m2​，将上一种情况对称处理即可。

每一次这样的截断，都会导致问题的考察规模降低一半。在每一层递归，时间开销仅仅是 O(1)\mathcal{O}(1)O(1) 的比对操作，因此在这种等长状态下，算法的时间复杂度被压缩成了 O(log⁡n)\mathcal{O}(\log n)O(logn)。

对于任意长度的子向量（设 n1≤n2n_1 \le n_2n1​≤n2​），虽然算法在处理不对称的边界条件时增加了繁琐的数学计算，但其分治内核不变：

蛮力完全归并法 申请新内存，完整合并后取正中间元素 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​) O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​)
双指针线性遍历 不分配新内存，使用双指针推演，迭代至第 kkk 步停止 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​) O(1)\mathcal{O}(1)O(1)
二分与分治法 递归比较 ⌊k/2⌋\lfloor k/2 \rfloor⌊k/2⌋ 战略点，每次贪婪抛弃一半不可能元素 O(log⁡(min⁡(n1,n2)))\mathcal{O}(\log(\min(n_1, n_2)))O(log(min(n1​,n2​))) O(1)\mathcal{O}(1)O(1)

有序数组求中位数的分治，关键不是“随便丢掉一半”，而是成对丢掉同样数量的过小元素和过大元素。只要两边丢弃数量保持平衡，全局中位数的秩就不会漂移，剩下的子问题仍然是在找同一个目标秩。

K-选取问题

之前的算法均建立在数组已经具备局部有序这一假设之上。那么在一个无序数组中，如何找出排名第 kkk 的元素？这就构成了 k-selection 问题。当 k=⌊n/2⌋k = \lfloor n/2 \rfloork=⌊n/2⌋ 时，查找的便是无序序列的中位数。

全量排序与堆排序

全量排序 对整个输入数组发起一次快速排序或归并排序，随后只需访问下标为 kkk 的那个元素。然而，全量排序的过程将时间复杂度锁定在 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)。这虽然能够得到目标元素，但为了寻找第 1 名或中位数而排出完整全序关系，计算信息量超过了问题本身所需。

引入堆围绕堆的设计，演化出了三种常见的攻击策略：

  1. 构建全局小顶堆：将这 nnn 个无序元素一次性构建为一个小顶堆。这个建堆过程只需花费 O(n)\mathcal{O}(n)O(n) 的线性时间。随后连续调用 kkk 次 delMin() 弹出堆顶元素。每次弹出的结构重整代价是 O(log⁡n)\mathcal{O}(\log n)O(logn)，因此总时间消耗为 O(n+klog⁡n)\mathcal{O}(n + k \log n)O(n+klogn)。当 kkk 很小（例如仅寻找全局最小的 3 个元素）时，这种方法较快；但一旦任务变为寻找中位数（即 k=n/2k = n/2k=n/2），复杂度会退化至 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)。

  2. 维持小规模大顶堆：也可以仅截取前 kkk 个元素，将它们构建成一个大顶堆，代价为 O(k)\mathcal{O}(k)O(k)。随后遍历剩下的 n−kn-kn−k 个元素，如果当前元素比堆顶的最大值还要小，就替换堆顶并重新执行下滤操作。全局遍历完毕后，总时间消耗为 O(k+(n−k)log⁡k)\mathcal{O}(k + (n-k) \log k)O(k+(n−k)logk)。在寻找中位数的场景下，其复杂度依然是 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)。

  3. 双堆维护：更复杂的设想是将输入数据划分为规模为 kkk 的大顶堆与规模为 n−kn-kn−k 的小顶堆。此后两个堆反复提取各自的堆顶进行比较并交换，直到大顶堆的最大值小于小顶堆的最小值。这种模型依旧无法在时间复杂度上突破全量排序的量级。

快速选择算法

在每一轮 QuickSelect 中，从当前的数组中随机挑选出一个 pivot，并根据其的数值大小，将整个数组切割成三个部分：

  • LLL （Left）：所有严格小于 pivot 的元素。
  • EEE （Equal）：所有与 pivot 完全相等的元素。
  • GGG （Greater）：所有严格大于 pivot 的元素。

无论这三个部分内部的元素排列如何，pivot 已经处在全局排序后它应在的秩区间中。此时，如果目标秩 kkk 落在 EEE 对应的秩范围内，那么搜索结束；如果目标秩 kkk 落在 LLL 中（即 k≤∣L∣k \le |L|k≤∣L∣），则不再搜索 EEE 和 GGG，仅在子集 LLL 中继续寻找，反之亦然。

QuickSelect 每一轮只需要知道目标秩落在哪个分区。如果按从小到大的第 kkk 小来记，且 ∣L∣<k≤∣L∣+∣E∣|L| < k \le |L|+|E|∣L∣<k≤∣L∣+∣E∣，答案就是 pivot；若 k≤∣L∣k \le |L|k≤∣L∣，继续在 LLL 中找第 kkk 小；若落在 GGG 中，则在 GGG 中找第 k−∣L∣−∣E∣k-|L|-|E|k−∣L∣−∣E∣ 小。代码实现时最容易出错的地方就是这一步的秩换算。

性能期望分析： 如果在每一次抽取轴点时，我们都能抽到将数组精确等分为两半的中位数作为 pivot，那么整个算法的问题探测规模将会按照 n,n/2,n/4,n/8...n, n/2, n/4, n/8...n,n/2,n/4,n/8... 这样的规模指数级衰减。由于 ∑i=0∞n2i=2n\sum_{i=0}^{\infty} \frac{n}{2^i} = 2n∑i=0∞​2in​=2n，整个算法消耗的总时间将是 O(n)\mathcal{O}(n)O(n)。

QuickSelect 并不需要这种极端的幸运。我们记算法的期望比较次数为 T(n)T(n)T(n)。在随机抽取基准的情况下，每一次划分会产生 000 到 n−1n-1n−1 规模的不等分。其期望时间满足以下递推：

T(n)=(n−1)+1n∑k=0n−1max⁡(T(k),T(n−k−1))≤(n−1)+2n×∑k=n/2n−1T(k)≤(n−1)+2n×∑k=n/2n−14k≤(n−1)+3n<4nT(n) = (n-1) + \frac{1}{n}\sum_{k=0}^{n-1}\max(T(k), T(n-k-1)) \le (n-1) + \frac{2}{n} \times \sum_{k=n/2}^{n-1}T(k) \le (n-1) + \frac{2}{n} \times \sum_{k=n/2}^{n-1}4k \le (n-1) + 3n < 4n T(n)=(n−1)+n1​k=0∑n−1​max(T(k),T(n−k−1))≤(n−1)+n2​×k=n/2∑n−1​T(k)≤(n−1)+n2​×k=n/2∑n−1​4k≤(n−1)+3n<4n

这个递推式，可以通过放缩和数学归纳法证明 T(n)≤4nT(n) \le 4nT(n)≤4n。即 QuickSelect 的期望时间复杂度是线性的 O(n)\mathcal{O}(n)O(n)。

然而，如果数组的初始分布处于极端情况（例如输入数组已经正序或逆序排列），而算法又总是挑选最大或最小元素作为 pivot，每一次耗费 O(n)\mathcal{O}(n)O(n) 时间进行划分后，只能剔除 1 个元素。平衡分治树在此退化为一条单向链表，整个系统的时间复杂度上升至 O(n2)\mathcal{O}(n^2)O(n2)。那么如何应对这一极端情况，将时间复杂度稳定在 O(n)\mathcal{O}(n)O(n)？

BFPRT 算法

算法实现

BFPRT 算法的目标是避免 QuickSelect 在最坏情况下退化。它通过构造具有稳定质量的 pivot，确保每一次划分都能丢弃一个恒定比例的元素，从而保证最坏情况下的线性时间复杂度。

如果需要在大量元素中选出一个质量足够好的划分轴点（即不会过于接近最大值或最小值的元素），可以使用“中位数的中位数”机制。算法的执行流程由以下五步组成：

  1. 粗粒度切分：首先将拥有 nnn 个无序元素的原始数组切分，均匀划分为 ⌊n/Q⌋\lfloor n/Q \rfloor⌊n/Q⌋ 个独立子序列。每个完整子序列包含 QQQ 个元素。对于零头元素，通常直接并入最后一个不足 QQQ 的子序列或忽略，不影响渐近边界。
  2. 局部排序：针对这些子数组，使用常数代价的插入排序对它们进行内部排序。在每个排好序的小组中挑出中位数。通过这轮选择，构建出一组规模约为原先 1/Q1/Q1/Q 的代表集合，记为 TTT。
  3. 递归自身：面对这个由约 n/Qn/Qn/Q 个代表元素组成的 TTT，为了选出质量稳定的 pivot，算法递归调用 BFPRT，找出 TTT 的中位数 MMM。这个 MMM 就是“中位数的中位数”。
  4. 划分：算法像 QuickSelect 那样，将 MMM 作为 pivot，在原数组中进行扫描。将原数组分为三个部分：LLL、EEE、GGG。
  5. 在子区间递归：最后，算法根据 kkk，判断它所在的区段（比较 kkk 与 ∣L∣|L|∣L∣ 以及 ∣L∣+∣E∣|L|+|E|∣L∣+∣E∣ 的关系），在相应的、规模已经缩减后的子区间中继续搜索。

BFPRT 的核心是用额外的线性工作换来“足够不坏”的轴点，而不是一定找出真正的全局中位数。分组大小通常取 5，是因为它既能保证每组中位数提供足够的淘汰比例，又不会让组内排序和递归常数过大。只要每轮能稳定丢弃一个固定比例的元素，最坏情况就能保持线性。

在步骤 3 中得到的 MMM，在最坏情况下也不会靠近最大/最小值边缘。在第 2 步中，我们建立了约 n/Qn/Qn/Q 个小组。在第 3 步中，MMM 成为了这些组中位数的中位数。这意味着，在由中位数组成的 TTT 中，有一半小于或等于 MMM。换言之，至少存在 12×nQ=n2Q\frac{1}{2} \times \frac{n}{Q} = \frac{n}{2Q}21​×Qn​=2Qn​ 个原始数组中的子数组，它们的组中位数小于或等于 MMM。

考虑这 n2Q\frac{n}{2Q}2Qn​ 个子数组。对于其中任意一个，既然其组中位数 ≤M\le M≤M，那么该组中位数及其左侧的 ⌊Q/2⌋\lfloor Q/2 \rfloor⌊Q/2⌋ 个元素也都 ≤M\le M≤M。因此，每个这样的完整小组至少提供 ⌊Q/2⌋+1\lfloor Q/2 \rfloor + 1⌊Q/2⌋+1 个不大于 MMM 的元素。若采用 BFPRT 常用的 Q=5Q=5Q=5，则每组至少提供 3 个元素。因此，原序列中小于等于 MMM 的元素总数下限至少为：

3×n2Q=3n2Q3 \times \frac{n}{2Q} = \frac{3n}{2Q} 3×2Qn​=2Q3n​

这意味着，当我们在步骤 4 中进行划分时，小于等于 MMM 的元素数量至少构成总元素数量的 32Q\frac{3}{2Q}2Q3​。同理，大于等于 MMM 的元素数量也至少有 32Q\frac{3}{2Q}2Q3​ 的下限。当 Q=5Q=5Q=5 时，每轮至少能在一侧排除约 3n/103n/103n/10 个元素，从而避免时间复杂度退化到 O(n2)\mathcal{O}(n^2)O(n2)。
