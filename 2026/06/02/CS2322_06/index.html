ADS-06：中位数与众数

|浏览量:

众数

众数的定义

给定一个包含 nnn 个元素的无序向量或数组，如果其中存在某个元素，其出现的总次数严格大于向量总长度的一半（即出现次数 >⌊n/2⌋> \lfloor n/2 \rfloor>⌊n/2⌋），则该元素被正式定义为这个向量的“众数” 。这种严格定义与统计学中通常意义上的“出现频率最高的数”（即频繁数 Mode）有所不同。 为了明确这一概念，我们可以考察以下两个具体实例：

  • 在序列 {3, 5, 2, 3, 3} 中，总长度为 5。元素 3 出现了 3 次。因为 3>⌊5/2⌋=23 > \lfloor 5/2 \rfloor = 23>⌊5/2⌋=2，所以 3 绝对占据了主导地位，是该序列的众数 。
  • 在序列 {3, 5, 2, 3, 3, 0} 中，总长度增加到了 6。元素 3 依然只出现了 3 次。根据严格定义，由于 333 并不严格大于 6/2=36/2 = 36/2=3，因此在这个特定的向量中，根本不存在任何众数 。

面对这个问题，有以下两种“平凡算法”：

  1. 全量排序结合线性扫描： 既然目标是寻找出现次数极多的元素，最符合人类直觉的操作是将杂乱无章的元素重新排列。如果使用快速排序或归并排序对整个数组进行升序排列，所有相同的元素必定会在数组中连续地紧挨在一起。此时，只需再进行一次极其简单的时间复杂度为 O(n)\mathcal{O}(n)O(n) 的线性扫描，记录连续相同元素的个数，一旦发现某个元素的计数超过了 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ 即可立刻返回。这种方法的算法瓶颈显然在于排序阶段，其时间复杂度为 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)，空间复杂度取决于所选用的排序算法（如归并排序需要 O(n)\mathcal{O}(n)O(n) 的辅助空间，快速排序需要 O(log⁡n)\mathcal{O}(\log n)O(logn) 的递归栈空间） 。 更有趣的是，从必要性条件来看，如果一个序列真的存在众数，那么在对其进行完整排序之后，该众数必定会覆盖数组的正中间位置 。这意味着，众数如果存在，它必然同时也是该序列的中位数。在学术界早期的探索中，寻找众数的过程往往依赖于寻找中位数的算法。

  2. 散列表统计法：另一种典型的“空间换时间”策略是利用散列表数据结构。遍历整个数组，将每个元素作为键（Key），将其出现的次数作为值（Value）存储在散列表中。如果某个元素的计数值在累加过程中超过了阈值 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋，则宣告找到了众数。这种方法得益于散列表 O(1)\mathcal{O}(1)O(1) 的平摊查找时间，能够将整体时间复杂度压缩至完美的线性 O(n)\mathcal{O}(n)O(n)。然而，这种性能的提升是以牺牲空间为代价的。在最坏情况下（例如数组中绝大多数元素都各不相同），散列表需要额外的 O(n)\mathcal{O}(n)O(n) 级别内存空间来存储键值对信息。

能否设计出一种算法，其执行时间严格不超过线性边界 O(n)\mathcal{O}(n)O(n)，且运行过程中所需的附加内存空间严格不超过常数级别 O(1)\mathcal{O}(1)O(1)？

Boyer-Moore 多数投票算法

Boyer-Moore 算法的核心哲学可以被深刻地概括为“减而治之”以及“异类相消”策略 。该算法能够在仅需常数级别的内存（几个标量变量）以及单次线性时间遍历的前提下，极为巧妙地找出一个序列中潜在的众数候选者 。算法的运行状态机十分精简，只需在内存中维护两个局部状态变量：

  • majority_candidate：用于记录当前轮次可能成为众数的候选元素。
  • counter：用于记录该候选元素的“生命值”或“对抗余量”，初始值设为 0 。

算法从前向后逐一处理序列中的每一个元素 xxx，其内部逻辑表现为极简的分支判断 ：

  1. 重置阶段：当读取到一个新元素 xxx 时，如果此时计数器 counter 恰好为 0，这表明之前的候选者已经在对抗中耗尽了所有的优势。算法将毫不犹豫地抛弃旧候选者，将当前元素 xxx 强行扶正为新的 majority_candidate，并同时将其生命值 counter 设置为 1 。

  2. 对抗阶段：如果此时 counter 并不为 0，说明当前已有在任的候选者。算法会将新读取的元素 xxx 与当前的 majority_candidate 展开比对：

    • 如果它们是相同的元素，这意味着候选者获得了“同阵营”的支持，其生命值 counter 将递增 1 。
    • 如果它们不相同，这意味着遭遇到“敌对阵营”的攻击。候选者需要消耗自身的一个支持者与该敌对元素进行一比一的“同归于尽”。此时，计数器 counter 将递减 1 。

当整个数组的所有元素都被这台状态机处理完毕后，最后依然驻留在 majority_candidate 变量中的元素，便被锁定为整个序列唯一的众数候选者 。

假设输入数组为 1, 2, 3, 2, 2, 2, 4, 2, 2（共 9 个元素，其中 2 出现了 6 次，显然是众数） 。

减而治之的第二遍扫描

如果在遍历过程中的某一个特定时刻 ttt，计数器 counter 恰好被减为了 0，这意味着什么？ 这表明，在刚刚被扫描过的一个长度必定为偶数的前缀子序列 PPP 中，被选定为阶段候选者的元素与其余所有不等于该候选者的敌对元素，在数量上实现了 1:1 抵消 。

此时，整个原序列向量 AAA 就在逻辑上被切割成了两半：前缀 PPP 和剩余的后缀序列 A−PA - PA−P 。 根据众数的数学定义，如果原序列 AAA 中确实隐藏着一位众数 mmm，那么：

  1. 由于在刚刚被剔除的前缀 PPP 中，所有的元素都两两同归于尽了，mmm 在这个局部群体 PPP 中所占据的比例最多只能是正好一半（即它作为候选人被其他元素全部抵消掉，或者它作为敌对者把别人抵消掉） 。
  2. 这就引出了一个极为关键的推论：既然 mmm 在全局中占据了绝对多数（超过一半），而在抛弃的前缀 PPP 中最多只占据一半，那么在剩下的后缀序列 A−PA - PA−P 中，mmm 所占的比例不仅绝对不会被稀释，反而会被进一步提纯和放大 。
  3. 换句话说，向量 AAA 拥有众数，当且仅当在其剥离掉前缀 PPP 之后的后缀 A−PA - PA−P 中，也拥有完全相同的众数 mmm 。

通过这种方式，算法持续不断地将能够互相抵消的前缀剥离，从而极大地缩小了问题的考察规模 。 majCandidate 函数通过 c == 0 判断当前前缀是否抵消殆尽，并在随后的扫描中动态调整 majCandidate 的指向 。

然而，算法同样隐藏着一个巨大的陷阱。 Boyer-Moore 算法的第一遍扫描过程虽然完美，但它提供的仅仅是一个关于众数存在的“必要条件”：它在数学上只能向你保证，假如这个序列确实存在一个众数，那么这个众数必定是最终残留在候选变量里的那个人 。 但是，如果这个世界的初始设定就是没有众数的呢？例如给定的序列是 1, 2, 3, 4, 5，每个元素都只出现了一次 。算法依然会机械地执行抵消逻辑，并在最后吐出一个任意的幸存者（比如在这个例子中可能是 5）。很显然，这个幸存者根本不是众数，因为整个数组压根就没有众数 。如果仅仅执行一遍算法而不加验证，算法将悄无声息地向调用者返回一个虚假的、可能是任意的元素作为结果，它无法自我检测“众数不存在”这一客观事实 。

因此，除非问题域已经绝对保证输入序列中一定存在众数，否则我们必须对数组发起第二遍独立扫描 。第二遍扫描的目的纯粹是为了审计：统计第一遍跑出来的这位“候选总统”在原数组中到底获得了多少张真实的选票。只有当它的总得票数严格大于 ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ 时，我们才能最终确信其众数的合法地位并将其输出；否则通过返回空值或抛出异常来表明该序列不存在众数 。

中位数

在长度为 nnn 的有序序列 SSS 中，元素 S[⌊n/2⌋]S[\lfloor n/2 \rfloor]S[⌊n/2⌋] 被称作中位数 。事实上，正如前文所提及的，寻找中位数本质上是寻找第 kkk 大元素（k-selection 问题）的一个极为苛刻的特例（当 k=⌊n/2⌋k = \lfloor n/2 \rfloork=⌊n/2⌋ 时）。

先来解决一个在归并排序框架下极为核心且经典的衍生子问题：假设存在两个已经各自完全排序的数组，如何以极致的速度找出它们合并后的全局中位数？

蛮力归并与及其优化

假设系统任意给定了两个有序向量 S1S_1S1​ 和 S2S_2S2​，它们的长度分别为 n1n_1n1​ 和 n2n_2n2​ 。

最符合直观的蛮力算法是这样的：既然这两个数组内部都已经排好序了，那最简单粗暴的方法不就是直接把它们按顺序合并成一个新的全局有序数组 SSS 吗？合并完成之后，直接根据数组的索引，揪出位于 S[(n1+n2)/2]S[(n_1 + n_2)/2]S[(n1​+n2​)/2] 这个正中间位置的元素即可 。 这种做法由于需要依次访问并搬运每一个元素到全新的内存空间中，其执行的时间复杂度为 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​)，更为致命的是，它还需要额外开辟 O(n1+n2)\mathcal{O}(n_1 + n_2)O(n1​+n2​) 的连续空间来存放这个临时的大数组 。 这种方法虽然因为效率低下而不适合处理海量数据。

二分查找与分治法

能否突破线性的枷锁，找到一种对数级别 O(log⁡(n1+n2))\mathcal{O}(\log(n_1+n_2))O(log(n1​+n2​)) 的算法？它的最优解法，必然要求我们充分利用两个数组已经有序这一信息，从而利用分治策略 。

首先考察最为理想的等长子向量情况（即假设 S1S_1S1​ 和 S2S_2S2​ 的长度一致，均为 nnn）。 此时，我们不再像双指针法那样慢吞吞地从头开始比较，而是直接提取出两个数组各自内部的中位数进行比对：令 m1=S1[⌊n/2⌋]m_1 = S_1[\lfloor n/2 \rfloor]m1​=S1​[⌊n/2⌋]，同时令 m2=S2[⌊(n−1)/2⌋]m_2 = S_2[\lfloor (n-1)/2 \rfloor]m2​=S2​[⌊(n−1)/2⌋] 。 其结果会引发三种分支：

  1. 若 m1=m2m_1 = m_2m1​=m2​，由于这两个局部中位数相等，并且各自刚好大于原来数组中一半的成员，它们顺理成章地不仅是各自数组的中位数，也必然是合并后数组的全局中位数。算法至此结束，直接将该值返回 。
  2. 若 m1<m2m_1 < m_2m1​<m2​，S1S_1S1​ 的前半部分（即所有严格小于等于 m1m_1m1​ 的底层元素），由于连 m2m_2m2​ 都不如，它们在合并后的数组中注定只能在前半截徘徊，它们不可能攀升到全局中位数的位置。同理，S2S_2S2​ 的后半部分，其必定会位于全局序列的后方，同样不可能成为中位数。 基于这一事实，我们可以将将 S1S_1S1​ 的前半部分和 S2S_2S2​ 的后半部分直接排除在搜索范围之外 。更为精妙的是，在这个截断的过程中，极小元素集合与极大元素集合的数量在数学上保持了平衡一致。因此，，中位数并没有发生任何漂移 。
  3. 若 m1>m2m_1 > m_2m1​>m2​，只需要将上一种情况对称过来处理即可。

每一次这样的截断，都会导致问题的考察规模降低一半。在每一层递归，时间开销仅仅是 O(1)\mathcal{O}(1)O(1) 的比对操作，因此在这种等长状态下，算法的时间复杂度被压缩成了 O(log⁡n)\mathcal{O}(\log n)O(logn) 。

对于任意长度的子向量（设 n1≤n2n_1 \le n_2n1​≤n2​），虽然算法在处理不对称的边界条件时增加了繁琐的数学计算，但其分治内核不变 ：

K-选取问题

之前的算法均建立在数组已经具备局部有序这一假设之上。那么在一个毫无任何秩序可言的混沌数组中，如何找出排名绝对第 kkk 大的元素？这就构成了k-selection问题。不难推想，当 k=⌊n/2⌋k = \lfloor n/2 \rfloork=⌊n/2⌋ 时，我们查找的便是无序序列的中位数 。

全量排序与堆排序

全量彻底排序 对整个输入数组发起一次快速排序或归并排序，随后只需访问下标为 kkk 的那个元素。然而，全量排序的过程将时间复杂度锁定在 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn) 。这虽然在功能上完美达成了目的，但实际上却是在进行一场极度的算力浪费。试想，你仅仅是为了寻找第 1 名，或者寻找中位数，却不惜花费海量的代价将所有名次彻底排出一个毫无争议的全序关系，这种由于信息索取过度而导致的不经济是显而易见的 。

引入堆围绕堆的设计，演化出了三种常见的攻击策略 ：

  1. 构建全局小顶堆：将这 nnn 个混沌的元素一次性灌入并构建为一个巨大的小顶堆。这个建堆过程只需花费 O(n)\mathcal{O}(n)O(n) 的线性时间。随后连续调用 kkk 次 delMin() 弹出堆顶元素。每次弹出的结构重整代价是 O(log⁡n)\mathcal{O}(\log n)O(logn)，因此总时间消耗为 O(n+klog⁡n)\mathcal{O}(n + k \log n)O(n+klogn) 。当 kkk 极其微小（例如仅仅是寻找全局最小的 3 个元素）时，这种方法很快；但一旦任务变得极端，比如寻找中位数（即 k=n/2k = n/2k=n/2），其背后的乘法效应会使得复杂度瞬间剧烈膨胀退化至 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)，被打回原形。
  2. 维持微型大顶堆：我们也可以逆向思维，仅仅截取前 kkk 个元素，将它们构建成一个极其精简的大顶堆，代价仅为 O(k)\mathcal{O}(k)O(k)。随后，我们遍历剩下的 n−kn-kn−k 个元素，如果当前路过的元素比堆顶的最大值还要小，我们就将其剔除，换上新元素并重新执行下滤操作。全局遍历完毕后，总时间消耗定格在 O(k+(n−k)log⁡k)\mathcal{O}(k + (n-k) \log k)O(k+(n−k)logk) 。不幸的是，在寻找中位数的极端场景下，其复杂度依然维持在 O(nlog⁡n)\mathcal{O}(n \log n)O(nlogn)。
  3. 双堆对抗：更为复杂的设想是将输入数据彻底劈开，任意划分为规模为 kkk 的大顶堆与规模为 n−kn-kn−k 的小顶堆。在此之后，两个堆反复不断地提取各自的堆顶进行比较并强行交换，直到大顶堆的最大值小于小顶堆的最大值 。这种模型依旧无法在根本的时间复杂度上实现维度的跨越。

快速选择算法

在每一轮 QuickSelect 中，从当前的数组中随机挑选出一个 pivot，并根据其的数值大小，将整个数组切割成三个部分 ：

  • LLL （Left）：所有严格小于 pivot 的元素。
  • EEE （Equal）：所有与 pivot 完全相等的元素。
  • GGG （Greater）：所有严格大于 pivot 的元素。

无论这三个部分内部的元素排列多么混沌无序，作为标杆的 pivot 已经在不知不觉中，被安放在了如果这个数组被全局排序后它所应在的绝对最终正确位置上。 此时，如果我们发现这个绝对位置恰好就是我们要寻找的第 kkk 名，那么搜索结束；如果我们要寻找的名次 kkk 依然埋藏在 LLL 中（即 k≤∣L∣k \le |L|k≤∣L∣），我们就可以不再搜索 EEE 和 GGG ，仅在子集 LLL 中继续寻找，反之亦如此 。

性能期望分析： 如果在每一次抽取轴点时，我们都能抽到将数组精确等分为两半的中位数作为 pivot，那么整个算法的问题探测规模将会按照 n,n/2,n/4,n/8...n, n/2, n/4, n/8...n,n/2,n/4,n/8... 这样的规模指数级衰减。由于 ∑i=0∞n2i=2n\sum_{i=0}^{\infty} \frac{n}{2^i} = 2n∑i=0∞​2in​=2n，整个算法消耗的总时间将是 O(n)\mathcal{O}(n)O(n) 。

QuickSelect 并不需要这种极端的幸运。我们记算法的期望比较次数为 T(n)T(n)T(n)。在随机抽取基准的情况下，每一次划分会产生 000 到 n−1n-1n−1 规模的不等分。其期望时间满足以下递推：

T(n)=(n−1)+1n∑k=0n−1max⁡(T(k),T(n−k−1))≤(n−1)+2n×∑k=n/2n−1T(k)≤(n−1)+2n×∑k=n/2n−14k≤(n−1)+3n<4nT(n) = (n-1) + \frac{1}{n}\sum_{k=0}^{n-1}\max(T(k), T(n-k-1)) \le (n-1) + \frac{2}{n} \times \sum_{k=n/2}^{n-1}T(k) \le (n-1) + \frac{2}{n} \times \sum_{k=n/2}^{n-1}4k \le (n-1) + 3n < 4n T(n)=(n−1)+n1​k=0∑n−1​max(T(k),T(n−k−1))≤(n−1)+n2​×k=n/2∑n−1​T(k)≤(n−1)+n2​×k=n/2∑n−1​4k≤(n−1)+3n<4n

这个递推式，可以通过放缩和数学归纳法证明 T(n)≤4nT(n) \le 4nT(n)≤4n。即 QuickSelect 的期望时间复杂度是线性的 O(n)\mathcal{O}(n)O(n) 。

然而，如果数组的初始分布处于极端情况（例如输入数组已经呈现出完美的正序排列或逆序排列），而我们又总是挑选中最大或最小的那个元素作为 pivot。 每一次耗费 O(n)\mathcal{O}(n)O(n) 时间进行的大规模扫描划分，只能剔除掉 1 个无关紧要的元素。平衡分治树在此退化为一条单向链表。整个系统的时间复杂度飙升至 O(n2)\mathcal{O}(n^2)O(n2) 。 那么如何应对这一极端情况的限制，将时间复杂度稳定在 O(n)\mathcal{O}(n)O(n)？

BFPRT 算法

算法实现

BFPRT 算法的目标很简单：彻底粉碎 QuickSelect 算法在最坏情况下发生病态退化的任何可能，构建一套具有极强自我修复能力的机制。确保在每一次划分中，无论初始分布多么恶劣，选出的那个 pivot 都必定拥有足够卓越的“中立”属性。凭借这个基准，算法能够在最坏情况下强行舍弃掉一个恒定比例的元素群。

如果我们需要在大量元素中海选出一个极其优秀的划分轴点（即一个必定紧紧依附在全局绝对中位数附近的优质元素），最符合逻辑且容错率极高的候选机制是什么？算法的执行生命周期由以下五步组成 ：

  1. 粗粒度切分：首先将拥有 nnn 个混沌元素的原始数组切分，均匀划分为 ⌊n/Q⌋\lfloor n/Q \rfloor⌊n/Q⌋ 个微小的独立子序列。每个微小子序列包含绝对固定的 QQQ 个元素。对于零头元素，通常直接并入最后一个不足 QQQ 的残阵或忽略，不影响渐近边界 。
  2. 局部排序：立刻针对这 n/5n/5n/5 子数组，使用常数代价的插入排序对它们进行内部排序。在每个排好序的小组中，精准地挑出中位数 。通过这轮海选，我们构建出了一组规模被浓缩至原先 1/Q1/Q1/Q 的精英代表集合，我们将其命名为 TTT。
  3. 递归自身：面对这个由 n/Qn/Qn/Q 个提炼的元素组成的 TTT，为了选出最佳 pivot，算法对自己施加深度递归调用（调用 BFPRT 自身），找出它真正的中位数 MMM。这个 MMM，便是“中位数的中位数”。
  4. 划分：算法像 QuickSelect 那样，将 MMM 作为 pivot，在原数组中进行扫描。将原数组分为三个部分：LLL、EEE、GGG 。
  5. 在子区间递归：最后，算法根据 kkk，评估它所在的绝对区段（精密判断 kkk 与 ∣L∣|L|∣L∣ 以及 ∣L∣+∣E∣|L|+|E|∣L∣+∣E∣ 的数学界限关系），在相应的、规模已经缩减后的子区间中，进行最后的搜索 。

在步骤 3 中历经两轮选择得到的 MMM，在最极端的恶劣假设下，也绝对不可能滑向最大/最小值边缘 。在第 2 步的组建中，我们建立了 n/Qn/Qn/Q 个小组。 在第 3 步中，MMM 脱颖而出，成为了这 n/Qn/Qn/Q 个部元素的中位数。这意味着，在由中位数构成的 TTT 中，有一半是严格小于或者等于 MMM 的。 换而言之，放眼望去，必定存在着至少 12×nQ=n2Q\frac{1}{2} \times \frac{n}{Q} = \frac{n}{2Q}21​×Qn​=2Qn​ 这么多的原始数组中的子数组，它们小于等于 MMM 。

考虑这 n2Q\frac{n}{2Q}2Qn​ 个子数组。对于这其中的任何一个，既然连它们的组中位数都只能 ≤M\le M≤M，那么在这个拥有 QQQ 名原始成员的子数组内部，中位数以及那 ⌊Q/2⌋\lfloor{Q/2}\rfloor⌊Q/2⌋ 个排名连中位数都不如的绝对底层元素，这 ⌊Q/2⌋+1\lfloor{Q/2}\rfloor+1⌊Q/2⌋+1 个元素构成的一个“弱者同盟”。这几个弱小元素，在数值上必定也绝对小于等于 MMM。我们把这 n2Q\frac{n}{2Q}2Qn​ 个子数组的“弱者同盟”汇聚起来，在那个拥有 nnn 人的原序列中，绝对小于等于 MMM 的元素总数，在任何最极端的极限下，其规模下限至少也必须达到：

3×n2Q=3n2Q3 \times \frac{n}{2Q} = \frac{3n}{2Q} 3×2Qn​=2Q3n​

这意味着，当我们在步骤 4 中进行划分时，被打入小于等于 MMM 阵营的总数，至少构成了总元素数量的 32Q\frac{3}{2Q}2Q3​ 。同理被大于等于 MMM 阵营的人口，同样也至少有 32Q\frac{3}{2Q}2Q3​ 的底线 。这彻底杜绝了算法时间复杂度退化到 O(n2)\mathcal{O}(n^2)O(n2)。
