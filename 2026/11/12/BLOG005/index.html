这里定义了一个管线类，其中：

  • 持有的设备引用 lveDevice ，管线依赖其存在，因此生命周期贯穿 pipeline 的全流程（此处应但注意，一般来讲，直接持有这样一个引用是存在内存隐患的。如果设备在管线之前释放，这里就有可能解引用空指针。所以使用这一点是建立在 device 的存活周期覆盖 pipeline 生命周期这一前提上的）；

  • 定义了一个用于保存图形管线各阶段创建参数的结构体 PipelineConfigInfo；

几个专门提到的参数：

控制三角形组成的拓扑，比如比如在 list 模式下即为传入的每三个顶点组成一个三角形；在 strip 条带模式下就会与前两个顶点组成一个三角形.

控制顶点映射到屏幕像素中的显示范围。比如将 height 改成一半，那么最后出现的三角形会只被压到屏幕的上半边（注意 Vulkan 中的 y 坐标时向下的）。

控制裁剪矩形位置和范围。最终在屏幕上只会显示裁剪矩形范围内的部分。

按照顶点顺序顺时针/逆时针决定哪一边是看到的正面。

createGraphicsPipeline & createShaderModule

createShaderModule 函数进行 shader 的读取和句柄创建。而 createGraphicsPipeline 则调用这个函数创建句柄，并设置着色器相关的 configInfo。接下来使用构造 pipeline 类时传入的由 defaultPipelineConfigInfo 创建的管线配置信息设置 pipelineInfo，然后创建 pipeline。因此在析构函数中按照着色器句柄-管线的顺序来进行 destory。

因此在运行时收到验证层的消息：

这里需要注意的是，Vulkan 默认情况下 API 中的错误检查非常有限，即使是像将枚举设置为不正确的值或将空指针传递给必需参数这样简单的错误，通常也不会显式处理，只会导致崩溃或未定义的行为。因为 Vulkan 要求您对所做的每一件事都非常明确，所以很容易犯许多小错误，例如使用新的 GPU 功能，但忘记在创建逻辑设备时请求它（文档原文）。

因此使用验证层来做：

  • 对照规范检查参数的值，以检测滥用
  • 跟踪对象的创建和销毁，以查找资源泄漏
  • 通过跟踪调用来源的线程来检查线程安全性
  • 将每个调用及其参数记录到标准输出
  • 跟踪 Vulkan 调用以进行分析和重放

validation 相关的配置在 device 层的实现中，这一部分后面再说。
