计算机系统工程-12：网络分层与链路层

发表于2026-11-05|更新于2026-11-05|Note计算机系统工程
|浏览量:

网络分层

浏览器向服务器请求一个网页。浏览器需要告诉服务器想看哪个页面，操作系统需要让请求到达服务器上的 Web 服务，网卡则要把请求发给本地网络中的下一台设备。同一段数据沿途会经过几个协议，每个协议负责其中一部分工作。

层次 这一层处理什么 网页请求中的例子
应用层 定义通信双方交换的内容及其含义 浏览器用 HTTP 请求一个 URL 对应的资源，服务器返回 HTML
传输层 在两端主机之间传送数据，用端口区分应用 TCP 把字节按序交给对端，通过序号和确认发现丢失并重传
网络层 让数据包跨越多个网络到达目的主机 IP 包携带目的 IP 地址，每台路由器据此选择下一跳
链路层 在同一条链路上传递一帧数据 笔记本通过 Wi-Fi 把帧交给接入点，下一段链路可以使用以太网

在分层图里，可以横着找同一种协议，也可以竖着看一次通信会经过哪些层。左边的 OSI 模型从下到上是物理层、数据链路层、网络层、传输层、会话层、表示层和应用层。中间的 TCP/IP 模型把物理传输和成帧归入网络接口层，应用协议负责会话和数据表示等工作。右边是课程采用的划分，链路层负责一跳，网络层负责跨网络转发，端到端层在此基础上向应用提供服务。

协议与地址

应用先确定要找的服务。浏览器根据 URL 中的主机名查询 IP 地址，根据 URL 中的路径请求资源。文件传输可以用 FTP，发送邮件可以用 SMTP，收取邮件可以用 POP3。它们对请求和响应的解释不同，同一套网络都能承载这些应用。

数据到达一台主机后，还要交给相应的程序。TCP 和 UDP 都用端口号标明通信两端。下图中，两种首部的第一行都是源端口和目的端口。TCP 还带有序号、确认号、标志和窗口等字段，用来建立连接、恢复丢失的数据和控制发送速度。UDP 首部只有源端口、目的端口、长度和校验和，保留每条消息的边界，丢失后的处理由应用决定。代理可以终止一条连接再建立另一条，防火墙也可以按地址和端口筛选经过的流量。

IP 地址标识设备接入网络的接口。路由器收到包后，查看目的 IP 地址并查询转发表。以太网交换机在一段局域网内根据链路层地址转发帧。应用可以用同一种 IP 接口跨越以太网、Wi-Fi、光纤和蜂窝网络，只需各段链路都能承载 IP 包。协议栈因此常画成沙漏，腰部是 IP，上下两端容纳多种协议和传输技术。

共同的接口也解释了为什么网络规模会影响网络的价值。假设网络里有 NNN 个人都能互相通信，每个人就有 N−1N-1N−1 个潜在通信对象。两人之间的联系只算一次，全网共有 N(N−1)/2N(N-1)/2N(N−1)/2 对潜在通信伙伴。IP 层统一寻址与转发，各应用可以按自己的需要在端系统中增加可靠性等功能，无需途中的网络理解网页或邮件的内容。

逐层封装

沿着图从上往下读。应用给出一段数据，TCP 在前面加上 TCP 首部，组成报文段。IP 把整个报文段当作自己的载荷，加上 IP 首部，组成数据报。以太网再把 IP 数据报装进帧里，加上本跳的地址、类型和尾部校验字段。接收端反向处理，按帧的类型找到 IP，再按 IP 首部中的协议号找到 TCP，最后根据连接信息把数据交给应用。

例如，TCP 要发送 100 字节应用数据。假设 TCP 和 IPv4 都使用 20 字节的基本首部，报文段共 120 字节，IP 数据报共 140 字节。在普通以太网上再加上 14 字节 MAC 首部和 4 字节帧校验序列，得到 158 字节的帧。在线路上，网卡还先发送 8 字节的前导码和帧起始定界符。因此算链路开销时，要分清从哪里开始数。普通无 VLAN 标签的以太网 MAC 帧长为 64 至 1518 字节，其中能装的上层数据最多为 1500 字节。

图中字段也说明了每层怎样区分多种上层协议。IPv4 首部的 Protocol 字段标明载荷应交给 TCP、UDP 还是 ICMP。常用的 ping 通过 ICMP 回显请求和回显应答探测 IP 连通性。Total Length 给出整个 IP 数据报的长度，源地址和目的地址各占 32 位。TTL 限制转发跳数，首部校验和用来检测 IPv4 首部的差错。

一段应用数据也可能分成多个报文段发送。每经过一台路由器，入站链路的帧封装就结束了。路由器取出 IP 包，更新转发所需的字段，再按出站链路的规则装进新帧。两端主机要处理从链路层到应用层的完整协议栈，中间的 IP 路由器只需处理沿途转发所涉及的层次。

比特传输

共享时钟

芯片上的两个寄存器可以共用一个时钟。寄存器 A 在一个时钟沿更新输出，导线上的电压经过传播逐渐稳定，寄存器 B 在下一个时钟沿读取输入。时钟周期必须容得下电路和导线的延迟。两端都知道何时写、何时读，线上就只需传数据。

如果 A 和 B 各用自己的时钟，B 怎样判断数据已经稳定？一种方式是再接两根控制线。A 先把一个比特放到数据线上，等数据稳定，再改变 ready 信号。B 观察到 ready 变化后读取数据，随后改变 acknowledge 信号。A 收到确认，才用下一个比特替换数据线上的值。图中的箭头给出了三个信号各自的方向。

设信号从 A 传播到 B 需要 Δt\Delta tΔt 秒，反向耗时相同。即使忽略电路处理时间，A 也至少要等 2Δt2\Delta t2Δt 才能收到确认。一根数据线每次握手传 1 位，速率上限约为 1/(2Δt)1/(2\Delta t)1/(2Δt) bit/s。如果同时铺设 NNN 根数据线，每次握手可传 NNN 位，上限相应变为 N/(2Δt)N/(2\Delta t)N/(2Δt) bit/s。并行 SCSI 和早期打印机接口都用过并行传输。

恢复时钟

线缆越长，每位等一次应答的代价越高。串行链路让发送端按约定速率连续发送比特，多个比特可以同时在路上传播。USB 和 SATA 都采用串行传输。接收端面临的新问题是，自己的时钟与发送端略有偏差，读得太早或太晚都可能把一个比特认成相邻的比特。

接收端可以用锁相环（PLL）从输入信号恢复时钟。压控振荡器（VCO）先产生一个接近发送频率的本地信号。鉴相电路比较输入信号与本地信号，一种实现是将两者相乘并滤波，再用所得电压调整振荡器。经过反馈调节，本地时钟会跟上输入信号的频率和相位，接收端就能在电平稳定时采样。

频率略有偏差的两个时钟会逐渐错开。如果输入长时间保持同一电平，接收端就缺少校准时钟的依据。曼彻斯特编码把每一位分成前后两半，并规定两半电平相反。因此即使连续发送相同的数据位，接收端也能在每一位中间看到一次跳变。双方只需事先约定两个跳变方向分别代表哪个值。

图中的虚线划分比特周期。看中间连续的三个 1，黑色 NRZ 波形在这段时间保持高电平，红色波形在每个比特中点都从低变高。按图中的约定，上升沿表示 1，下降沿表示 0。有些系统采用相反的方向，把 0 编成 01、1 编成 10。两端采用同一约定，就能从跳变方向读出数据。每传一位需要两个码元，因此在相同的码元速率下，比特率降为每码元传一位时的一半。

链路复用

时分复用

波士顿和洛杉矶之间的一条干线可以同时承载多路电话。呼叫建立时，两端交换机为这路通话预留一个周期性时隙，通话结束再释放。接收端按时隙的位置区分通话，即使某人暂时不说话，他的时隙也保留下来。这种定期获得传输机会的通信方式适合连续传送语音样本。

假设每路电话每秒采样 8000 次，每个样本 8 位，每路需要 8000×8=64,0008000\times8=64{,}0008000×8=64,000 bit/s。每隔 1/80001/80001/8000 秒，也就是 125 微秒，每路都要送出一个样本。在 45 Mbit/s 的干线上，一个周期可发送 45,000,000/8000=562545{,}000{,}000/8000=562545,000,000/8000=5625 位。安排 703 路通话需要 703×8=5624703\times8=5624703×8=5624 位，恰好能放下。此处按课件的简化模型计算，暂不计额外的线路开销。下图相邻两个标出的 8 位样本属于同一路电话，中间的时间可以交给其他通话。

第 704 路电话呼入时会怎样？703 路各自占用一个时隙，剩下的 1 位装不下一个 8 位样本，新呼叫只能等待或收到忙音。已经接通的人仍听到连续的声音，因为接收端每 125 微秒就收到下一个样本，可以按原采样节奏还原语音。

分组复用

一台电脑下载文件时会连续收到许多数据，下载结束后却可能长时间空闲。给每台电脑预留固定时隙，会让空闲电脑占着线路。分组网络把数据拆成有限长度的包，每个包携带地址等控制信息，链路空闲时就发送一个等待中的包。例如，一个来源可以一次发送 4000 位数据，另一个来源随后只发 750 位。两份数据各自带有控制信息，接收端可以分别处理。长消息也可以分段，到接收端再重组。语音也可以分组传送，由接收端缓冲后按时播放。

图中不同颜色代表不同来源。多个输入同时需要同一个输出口时，交换设备把暂时发不出去的包放入队列，依次送上链路，这就是复用。收到包后，设备按首部中的目的地址查表，决定应交给哪个输出口，这就是分用。缓冲区使设备可以吸收短时突发，代价是排队等待，队列满后还可能丢包。无连接分组转发省去了逐次建立呼叫的步骤，设备仍需保存转发表和队列。

成帧与校验

帧的边界

接收端能读出 0 和 1 之后，还需要知道一帧从哪里开始、在哪里结束。一种简单的设计是用连续七个 1 作分隔符。为了让数据中的七个 1 可以原样还原，发送端每在数据里数到连续六个 1，就额外插入一个 0。例如，数据 1111111 在线上变成 11111101。接收端识别帧边界后，按同一规则去掉填入的 0。这种方法称为比特填充，采用哪一种标志和填充规则由具体协议规定。

检错与纠错

链路中的噪声可能让 1 变成 0，或者让 0 变成 1。发送端可以随帧附上校验值，接收端根据收到的数据重新计算。发现错误后，可以丢帧并由上层处理，也可以请求链路对端重发。后者要求发送端把尚未确认的帧保存在缓冲区。另一种做法是在发送或写盘前加入足够的冗余，使接收端或读盘设备能够自行恢复数据，称为前向纠错（FEC）。系统可以按误码特点和重传代价搭配这些方法。

检错和纠错的区别可以用汉明距离算出来。两个等长比特串中，取值不同的位置数就是它们的汉明距离。把两串按位异或再数 1，也能得到这个数。例如，100101 与 000111 异或得到 100010，其中有两个 1，说明这两串相差两位。编码规则允许发送的比特串称为码字。若任意两个码字至少相差 ddd 位，翻转少于 ddd 位就无法从一个合法码字变成另一个。只做检错时，接收端因此能发现最多 d−1d-1d−1 位错误。要纠正 ttt 位错误，还得保证收到的串只会落在一个码字的 ttt 位范围内，这要求 2t<d2t<d2t<d。

最小距离 接收端能据此做什么
2 检出任意一位翻转
3 纠正任意一位翻转。如果只做检错，可以检出两位翻转
4 在纠正一位错误的同时，认出两位错误并报告。若只做检错，可以检出三位翻转

以偶校验为例，在两位数据后加一位，让整串中 1 的个数为偶数。于是 00 → 000，01 → 011，10 → 101，11 → 110。三位比特共有八种组合，只有这四种是合法码字。图上沿一条边移动相当于翻转一位。从任何一个加粗的码字出发，走一步都会落在非法组合上，走两步却可能到达另一个合法码字。

汉明码

怎样用三个校验位定位一个错误？把四位数据装进七个位置，每次读取要区分八种情况，即七个位置中某一位出错，或所有位都正确。三个校验结果恰好能够表示 23=82^3=823=8 种情况。给较长数据块编码时可以共用校验位，例如 56 位数据用 6 个位置校验位就能定位单错，还可以加一位总奇偶校验来检测双错。

把七个位置从左到右编号为 1 至 7。位置 1、2、4 放校验位，位置 3、5、6、7 依次放数据位。每个校验位负责一组位置，各组分别检查编号的二进制表示中最低位、第二位和第三位为 1 的那些位置。

校验组 参与偶校验的位置 数据为 1101 时应填的校验位
1 1、3、5、7 位置 3、5、7 都是 1，因此位置 1 填 1
2 2、3、6、7 位置 3、6、7 为 1、0、1，因此位置 2 填 0
4 4、5、6、7 位置 5、6、7 为 1、0、1，因此位置 4 填 0

依次读出七个位置，得到码字 1010101。假如收到 1010001，第 1、4 组的偶校验失败，第 2 组通过。因为 1+4=51+4=51+4=5，出错的是第 5 位，把它翻转即可。若收到 1110101，只有第 2 组失败，因此恢复第 2 位。校验位自身出错也可以用同一方法定位。

如果三位同时翻转，会发生什么？从合法码字 1010101 出发，同时翻转第 1、2、3 位，得到 0100101。第 1 组有两位变动，第 2 组也有两位变动，第 4 组未受影响，三组检查全部通过。接收端会把它当作另一条合法数据。三位错误也可能导致错误的纠正结果，普通七位汉明码只保证纠正单错。

PPP

点对点链路两端各有一台设备。两端要就帧格式、接收能力和上层协议达成一致，才知道怎样解释对方送来的字节。点对点协议（PPP）把这些工作分开。链路控制协议 LCP 建立和配置链路，网络控制协议族 NCP 配置所承载的网络层协议，其中 IPCP 用于 IPv4。

在常见的 HDLC 风格封装中，PPP 帧的字段依次如下。两端先识别标志，再检查 FCS，通过校验后根据协议字段交付载荷。

字段 常用长度 含义
起始标志 1 字节 0x7E，比特表示为 01111110
地址、控制 各 1 字节 默认分别为 0xFF 和 0x03，沿用点对点成帧格式
协议 默认 2 字节 说明载荷类型，例如 0x0021 表示 IPv4
信息 可变 网络层数据报或 PPP 控制报文
帧校验序列 FCS 2 或 4 字节 使用 CRC 检测传输差错
结束标志 1 字节 同样为 0x7E，也可作为下一帧的起始标志

注意标志中间有六个连续的 1。在按位同步的 PPP 链路上，发送端每遇到五个连续的 1 就填一个 0，接收端再去掉它。异步字节链路则使用转义字节。成帧的目的相同，两种链路识别边界的单位不同。

假设路由器 A 能接收 1500 字节的信息字段，希望使用 32 位 FCS，路由器 B 只支持 16 位 FCS。双方先交换 LCP 配置请求和答复，调整未获同意的选项。两边各自的配置都得到确认后，链路进入打开状态。接下来 IPCP 协商 IPv4 所需的参数，然后 PPP 才开始承载 IPv4 数据报。这样，发送方在发出业务数据前就已知道对端能按什么条件接收。

跨网传输

一段链路只能把帧交给这一跳能接收它的设备。目的主机在远处时，发送方给 IP 层的是最终目的地址。每台路由器按转发表选择下一跳，再用本地链路把包送过去。控制平面负责生成和更新这张表，数据平面负责对每个到达的包查表并转发。链路故障、新增连接或代价变化都可能触发重新选路。小网络可以手工配置静态路由，规模增大后，路由器需要交换信息并自行更新路由。

IP 提供尽力而为的投递。路由器遇到无法转发的包或队列已满时可以丢包。应用需要可靠交付时，可以由传输层检测丢失并重传。另一种服务按完整消息跟踪交付，把等待转交的消息暂存在磁盘上，等下一站确认后再清理。它把持久化和重试放在更高一层。

超时也可能发生在回复途中。服务器若已执行请求，客户端此时重发同一请求，服务器就可能执行两次。例如读取网页通常可以重复，重复扣款就会改变余额。需要避免重复执行的服务，可以给请求分配标识，并记录已经处理的请求及其结果。
