计算机系统工程-13：IP 路由与转发

发表于2026-11-05|更新于2026-11-05|Note计算机系统工程
|浏览量:

下一跳

主机要把一个 IP 包发给远处的服务器，只要先把它交给一台能继续转发的路由器。对这个包来说，这台路由器就是主机的下一跳。随后每台路由器都查自己的转发表，根据目的 IP 地址决定下一跳和出接口。沿途各台设备的决定接得上，包才能到达服务器。

这些表是怎样得到的？管理员可以为出口固定的小网络配置静态路由。链路较多时，路由器会运行路由协议，发现邻居、交换可达信息，再选出到各目的地的路径。很多域内协议用 HELLO 报文发现邻居并确认它们仍能通信。路由器通告哪些目的地可以到达，以及到达它们的代价。链路中断或代价发生变化后，路由器再更新自己的选择。计算和更新路径属于控制平面，逐包查表和转发属于数据平面。

把路由器画成节点，直连线路画成边，边上的数表示代价。代价可以按跳数、带宽或管理员配置的度量确定。下面的例子用沿途各条边的代价之和比较路径。A 直连 B 的代价为 7，经 D 到 B 的代价为 2+1=32+1=32+1=3。因此 A 发给 B 的包，走代价较小的路径时，第一跳应该交给 D。

链路状态路由

链路状态路由（link-state routing）让每台路由器获得本区域的拓扑。以 A 为例，它先测得自己与 B、D、F 相邻，向邻居发出一份通告，列出 (B,7)、(D,2)、(F,1)。邻居把新通告转发到其他链路。路由器按发起者和序号识别已经处理过的版本，重复收到同一份就停止转发，也可以跳过刚刚送来这份通告的接口。这种逐跳传播称为泛洪。

B、D、F 等节点也会分别通告自己直连的链路。只要区域仍然连通，一条边故障的消息就可以沿其他边传遍区域。每台路由器把最新通告拼成带权图，再以自己为起点运行 Dijkstra 算法。OSPF 和 IS-IS 都采用这一思路。

最短路径

从 A 出发，先记下到自己的距离为 0，到其他节点的距离为无穷大。每一步都从尚未确定的节点中取当前距离最小的一个，记为 uuu。对它的每个邻居 vvv，尝试用“到 uuu 的距离加上边 uuu 到 vvv 的代价”改进到 vvv 的距离。由于链路代价非负，所有还未确定的路线都无法再把到 uuu 的距离降得更低，因此这一轮可以确定 uuu 的最短距离。

距离向量路由

距离向量路由（distance-vector routing）允许路由器只跟直连邻居交换消息。每台路由器维护一列“目的地、当前距离”，这列数就是它的距离向量。起初它只确定到自己的代价为 0。认识直连邻居后，就能列出直连代价。收到其他节点的向量时，路由器用这些数更新自己的估计，再向邻居通告自己的新向量。

计数到无穷

距离通告没有记录完整路径，故障发生前留下的旧通告可能造成环路。看一条更短的链 A—B—C，每条边的代价都是 1。起初 B 到 C 为 1，A 通过 B 到 C 为 2。图中 A 在 t=0,10,20,…t=0,10,20,\ldotst=0,10,20,… 通告，B 在 t=5,15,25,…t=5,15,25,\ldotst=5,15,25,… 通告。

  1. 在 t=9t=9t=9，B 发现到 C 的链路断开，将 C 记为不可达。A 此时仍保存着经 B 到 C 的旧记录。
  2. 在 t=10t=10t=10，A 报告“我到 C 的距离是 2”。B 看不到这条路经过自己，于是认为可以经 A 到 C，距离记为 1+2=31+2=31+2=3。
  3. 在 t=15t=15t=15，B 向 A 报告距离 3。A 本来就依赖 B，于是把自己的距离更新为 4。到 t=20t=20t=20，B 又把距离更新为 5。

此时两端都在把去 C 的包交给对方。协议会把某个有限数值定义为“无穷大”，直到距离涨到该值才判定不可达。取值太小，会把真实可达的长路径排除在外。取值越大，错误消息来回传播的轮次可能越多。RIP 把 16 跳定义为不可达，可用路径最多 15 跳。

水平分割（split horizon）可以消除图中的两节点误判。A 既然通过 B 到 C，就省略发回 B 的这条路由。采用毒性逆转（poisoned reverse）时，A 会向 B 明确报告这条路的距离为无穷大。两种做法都能让 B 看出 A 无法给它提供到 C 的备用路线。涉及更多节点的环路仍需要等待其他更新收敛。

交换开销

设区域内有 NNN 台路由器、LLL 条双向链路。在一次完整的链路状态发布中，每台路由器各发一份本地通告，每份泛洪到整个区域，按每条链路两个方向各转发一次估算，约需 2NL2NL2NL 次传输。随后各节点可在本地计算路径。距离向量的每一轮只需相邻双方各发一份向量，约为 2L2L2L 次传输，但一份向量包含许多目的地，而且新信息每轮只能再传播一跳。路径越长，传遍所需的轮数往往越多。这里比较的是消息次数，消息长度和收敛轮数也会影响实际开销。

分层路由

区域与前缀

如果每台路由器都为全球每个网络接口保存单独的表项，转发表和通告都会随接口数增长。可以给地址分层，例如把“11,75”解释为第 11 区域的第 75 号站。外部路由器只需保存如何到第 11 区域，包进入区域后，再按站号交给内部路由器。区域还可以继续划分，不同地区也可采用不同层数。

下图右侧是 R1.B 的两部分转发表。目的地是 R1.C 时，先匹配本区域，再查本地表，走 2 号接口。若目的地属于 R3，区域表直接给出 1 号接口，R1.B 无需知道 R3 内有哪些主机。代价是外部路由器看到的细节更少，有时会错过全网最短路径。地址也反映接入位置，设备搬到另一个区域时，通常要换到该区域的地址段。

互联网以自治系统（AS）划分管理范围。一个 AS 由同一管理方实施路由策略。AS 内可以运行 OSPF、IS-IS、RIP 或 EIGRP 等内部网关协议，按内部度量选择路径。承担域间通信的边界路由器还运行 BGP，与其他 AS 交换目的网络的可达信息。收到一个外部前缀后，AS 内部仍要把包送到合适的出口。

IP 用前缀表达一块连续、对齐的地址。CIDR 记法 18.0.0.0/24 表示前 24 位固定，后 8 位可以变化，覆盖 18.0.0.0 至 18.0.0.255。外部路由器可用一条通告代表这 256 个地址。分配连续地址块能减少表项。查表时优先采用匹配位数最多的前缀，因此大地址块内需要单独转发的一小块也能有自己的出口。

路径向量

考虑第三种通告方式。每个节点通告到目的地会经过哪些节点，收到通告的一方在路径前加上自己，并选出愿意采用的路径。节点到自己的路径起初可以记为空。图中的 G 通过 1 号接口连接 A，通过 2、3、4 号接口分别连接 H、J、K。得知 J 能直接到 D 后，G 可以记录经 J 到 D，随后把去 D 的包送到 3 号接口。边上的数字在这幅图里表示本机接口编号。

这就是路径向量（path vector）。如果 J 给 G 的候选路径已经包含 G，G 就丢弃它，否则把包交给 J 后还会回到自己。一个目的地有多条可行路径时，节点按本地规则选择。邻居加入新链路后可以通告新路径，原有路径失效时可以撤销，接收方随之删除依赖这条通告的路线，重新选择。相较只报距离的做法，通告更长，但接收者能识别路径中是否已有自己，避免前面逐次增加距离的过程。

BGP 策略

BGP 把路径向量用于自治系统之间，通告的目的地是 IP 前缀，路径中的编号代表 AS。相邻 BGP 路由器通过 TCP 建立会话，用 KEEPALIVE 维持会话，用 UPDATE 发布或撤销路由。有变化时发送增量更新，可靠传输由 TCP 提供。路由器通常会拒绝 AS 路径中已经含有本 AS 编号的候选项。

自治系统还要决定愿意替谁转发流量。最常见的两种关系是购买转接服务和对等互联。客户向上游付费，让上游把自己的流量送到互联网的其他地方。两个对等网络通常同意让自己的网络和客户访问对方及对方的客户。对等可以缩短路径并节省付给上游的费用，是否建立对等取决于双方的业务安排。

这些约定影响路由的接收和发布。常见的导入策略会优先选择从客户学到的路径，其次是对等方，最后是需要付费的上游。条件相同再比较其他路径属性。对外发布时，运营商通常向所有邻居通告自身及客户前缀，向客户提供更完整的路由，而从一个对等方或上游学到的路由通常只通告给客户。因此不同 AS 看到的可达路径可以不同。

读图时，把等号看成对等关系。C 是 Z 的客户，所以 Z 会向对等方 X 通告 C。X 会向 Z 和 Y 通告自己的客户 C1、C2、C3，Y 也会向 X 通告自己的客户 D。如果 X 再把从 Z 学来的 C 通告给 Y，Y 就会把发往 C 的流量交给 X，由 X 免费替两个对等方转接。按照图中的策略，X 会省略这条通告。X 同样会省略从上游 T 学来的路线，否则替 Y 转发还要向 T 付费。

图上 Y 没有经 X 到 C 的路由，它怎样访问 C？Y 可以向自己的上游购买转接。较小的网络可接入区域运营商，区域运营商再连接骨干运营商。顶层骨干之间通过对等互联交换可达信息，所以 Y 还可以从自己的上游学到另一条路。

BGP 需要同时处理可达性和各家的运营策略。一个网络接入多个上游时，同一个地址块可能出现更多候选路径，也可能需要发布更具体的前缀。配置错误或互相冲突的策略会让路由反复变化。AS 路径检查可以发现环路，却无法单凭一条通告证明发布者有权代表该前缀。2017 年 12 月，俄罗斯的 AS39523 异常通告了包含 Google、Apple、Facebook 和 Microsoft 在内的多个网络前缀，部分流量因此被引向错误的网络。

IP 包转发

收包与发包

路由算法算出表项后，每个到达的 IP 包都可以独立查表。下图中有两条入口。从左上开始，本机的传输层调用 NETWORK_SEND，交出一段数据、目的地址以及网络层和上层协议的标识。IP 层选定源地址，把上层协议号和载荷一起写入新包，再调用 NETWORK_HANDLE。从右下开始，网卡收到其他设备发来的帧，链路层取出载荷，按帧中的类型交给相应的网络层处理函数，也会进入 NETWORK_HANDLE。

如果目的 IP 属于本机，处理函数就按上层协议号交付载荷，并带上源地址。例如 IP 把 TCP 报文段交给 TCP，TCP 再按连接信息交给对应的 socket。如果是需要转发的 IPv4 包，路由器会执行以下操作。

  1. 按目的 IP 在转发表里做最长前缀匹配，取得出接口和下一跳。如果有默认路由，也可以匹配 0.0.0.0/0。找不到任何可用路由时，丢弃这个包。
  2. 将 TTL 减 1。若减到 0，丢弃这个包，通常向源端返回 ICMP 超时报文。这样即使转发表暂时形成环路，包也不会一直循环。
  3. 更新 IPv4 首部校验和，因为 TTL 字段已经改变。按出接口所用的链路协议，为下一跳加上新的帧封装，再从该接口发出。

软件转发

一块多端口网卡通常为各端口提供多组收包队列（RX）和发包队列（TX）。下图中的两个处理进程各负责一组队列。一台机器用 DPDK（Data Plane Development Kit）实现软件路由器时，可以让工作线程在用户态轮询自己的 RX 队列，成批取包，读取目的地址并查转发表，再把待发的包放入出端口的 TX 队列。这样可以绕过内核的常规收发路径，减少每包的中断和调度开销。图中 RX、TX 的编号是队列编号，同一端口可以由多个核分担。

RouteBricks 进一步把转发工作分到多台通用服务器。下图左边是传统路由器，输入口和输出口之间由机箱内的交换结构连接。右边把外部线路接到若干服务器上，服务器之间通过内部链路交换包。入站服务器需要从另一台机器的端口出包时，就先把包传给那台机器。每台服务器内部又能用多核并行处理不同队列，扩展转发能力时既能增加核心，也能增加服务器。

以太网与 ARP

共享介质

早期以太网把多台站点接在同一段介质上。站点先听线路，空闲时开始发送，同时继续监听是否发生冲突。两台相距较远的设备可能在对方信号尚未到达时都判断线路空闲，于是同时发送。检测到冲突后，双方停止当前传输，随机等待再试。连续冲突时扩大随机等待的范围，称为二进制指数退避。这套方法叫作带冲突检测的载波侦听多路访问（CSMA/CD）。

为什么共享以太网需要规定最短帧长？假设发送方刚要发完最短帧，远端才检测到冲突。冲突信号还得沿线路传回来，发送方必须仍在发送才能察觉。因此共享网段的最大往返延迟要受发送时间约束。经典 10/100 Mbit/s 半双工以太网的时隙是 512 比特时间，对应 64 字节最短 MAC 帧。把帧前的 8 字节前导码和定界符也数进去，一次最短发送在线上共占 576 比特时间。

实验以太网的速率约为 3 Mbit/s，后来的标准以太网、快速以太网和千兆以太网分别达到 10、100 和 1000 Mbit/s。理解这些数字时还要看端口如何连接。集线器（hub）把收到的信号复制到其他端口，所有设备共享带宽和冲突域。交换机（switch）学习“源 MAC 地址出现在哪个端口”，对已知目的 MAC 定向转发，广播帧和目的 MAC 未知的帧则在同一广播域内从其他端口发出。使用全双工点对点链路时，每个端口可以独立收发，链路长度主要受物理介质限制。

一块网卡在常规单播和广播通信中会接收发给自身 MAC 的单播帧，以及它所在广播域内的广播帧，再按类型字段把载荷交给 IPv4、ARP 等协议。共享介质上的其他单播帧通常会被网卡过滤。以太网广播地址是 ff:ff:ff:ff:ff:ff，同一广播域内每台主机都能收到，这给查找邻居提供了一个办法。

地址解析

下图有两套地址。上方的 L、M、N、E 是网络层标识，下方的 17、15、18、19 等是各站在这段以太网上的链路层标识。L 要向同一链路上的服务器 N 发 RPC，可以把包交给站 18。L 想访问远处的 E 时，则要先交给路由器 K 在本段上的站 19。即使 E 在另一段链路上碰巧也叫站 15，当前链路上的站 15 仍是 M。

在 IPv4 以太网上，主机先查路由，确定下一跳的 IP，再用 ARP（地址解析协议）查询这个 IP 对应的 MAC。若目的地就在本链路上，下一跳 IP 就是目的 IP。若目的地在外网，下一跳通常是本地网关。主机先查本地 ARP 缓存，找到有效记录即可直接封装。

若缓存为空，主机会在本地链路广播 ARP 请求，带上发送方的 IP 和 MAC，以及待查的目标 IP。图中的多个站都能收到请求，拥有目标 IP 的站通常把自己的 MAC 单播回复给请求者。请求者把映射暂存在缓存里，下次发包便可省去一次广播。ARP 报文中的硬件类型、网络协议类型、两种地址长度以及操作码，共同说明后续地址字段的意义。早期的 RARP 执行相反方向的查询，例如无盘主机已知自己的 MAC，启动时向服务器询问分配给它的 IP。

路由器一般不会把一段以太网上的 ARP 广播转到下一段。如果启用代理 ARP，路由器也可以代远端地址回答。例如 L 在本地询问 E，站 19 知道如何路由到 E，便用自己的链路地址回复。这样 L 临时保存的是“要到 E，把帧交给 19”。在普通的默认网关配置下，L 会直接查询网关的地址。

NAT

私有地址可以在多个网络中重复使用，例如两所学校内部都可以出现 10.8.8.8。公网不发布通往这些私有地址的路由，内网主机主动访问公网时，出口网关可以把源地址翻译为自己的公网地址。多个连接共用一个公网地址时，网关还要用传输层端口区分连接。这种转换称为 NAPT，也常称为端口地址转换（PAT）。

沿图中的箭头读一遍请求和回复。左上角是内网主机发出的 TCP 报文，右上角是同一份请求经过网关后的样子。底部是回复经过网关前后的样子，中间的红色表格是网关保存的映射。

观察位置 源 IP 和端口 目的 IP 和端口
内网主机发出的请求 192.168.1.2:54321 173.194.72.104:80
网关发往公网的请求 202.120.40.85:60001 173.194.72.104:80
服务器发回的回复 173.194.72.104:80 202.120.40.85:60001
网关交回内网的回复 173.194.72.104:80 192.168.1.2:54321

出站时网关分配了端口 60001，并记住它对应内网端点 192.168.1.2:54321。回复到达这个公网端口，网关便能还原内网目的 IP 和端口。第二条内网连接即使访问同一服务器，也可通过不同的外部端口区分。转换相关字段时，网关还要相应更新校验和。

网关必须保存有效映射才能正确分发回复，因此其转发能力和映射表容量会影响所有经过它的连接。如果应用协议把本机地址写进载荷，网关只改首部后，对方仍可能拿到一个无法从公网使用的私有地址。两个内网合并时也可能有重叠地址，例如两边都使用 10.0.0.0/24。要让同一个路由环境能区分这两组主机，就得重新规划地址或在边界做相应转换。

一次网页请求

图里校园网的三台主机共用一个网关。以 C 为例，它在示例中使用 192.168.0.4，网关内侧接口为 192.168.0.1，外侧为 202.120.40.82。不同网络接口上的 IP 分属各自连接的网络。右侧还有示例代理 106.185.46.164，配置代理的程序先与代理通信，再由代理向目标服务发起另一段通信。

以图中 C 直接访问百度为例，可以沿着第一个 TCP 连接请求，看清 IP 和 MAC 分别在什么时候改变。

  1. 应用通过 DNS 取得 www.baidu.com 的地址，示例中为 220.181.57.217。程序对这个服务器地址和服务端口调用 connect()，TCP 开始建立连接。
  2. C 的操作系统查路由表，发现目的 IP 在本地子网之外，应使用默认网关。若缓存中没有 192.168.0.1 的记录，C 先广播 ARP 查询网关的 MAC。随后 C 发出以太网帧，目的 MAC 填网关，里面的 IP 包仍以百度为目的地。
  3. 网关收到发给自己 MAC 的帧，取出 IP 包。目的 IP 属于远端，于是网关查转发表、更新 TTL。如果出口启用了端口地址转换，还会把私有源 IP 和源端口映射为公网端点。网关按照出接口的链路规则重新封装，交给下一跳。
  4. 后续路由器重复逐跳转发。最后一台路由器发现服务器所在网络与自己直连，在以太网上取得服务器的 MAC 并发帧。服务器回复时以它看到的公网端点为目的地，校园网关再按 NAT 表把回复交给 C。

C 明明知道服务器的 IP，为什么还要先查网关的 MAC？IP 地址指出最终目的地，目的 MAC 决定本段以太网上谁来接收这帧。远端服务器收不到校园网内部的广播，网关才是 C 在本段链路上能够直接交付的下一站。

ARP 欺骗

ARP 缓存保存的是本地设备接受的 IP 与 MAC 对应关系。若设备接受了伪造的响应，就可能把正确的 IP 与攻击者的 MAC 关联，称为 ARP 缓存投毒。设 T1、T2 与攻击者接在同一台交换机上。攻击者向 T1 声称“10.0.0.2 对应我的 MAC”。T1 若更新缓存，此后发往 T2 的 IP 包仍写着 T2 的 IP，但以太网帧会先送到攻击者。T2 无需接收到这份伪造响应，T1 的去程流量就已经改道。

图中两端都收到了伪造的响应。T1 把 T2 的 IP 映射到了攻击者，T2 也把 T1 的 IP 映射到了攻击者。若攻击者按真正的 MAC 把帧继续转给对端，双方仍可能保持通信，攻击者则位于两个方向的传输路径中，这就是中间人攻击。若攻击者直接丢弃帧，两端通信就会中断。

动态 ARP 条目会老化，也可能被真实响应纠正，所以伪造的映射需要反复刷新才能维持。课件以约 40 秒作为演示间隔，实际时长取决于系统的缓存策略。课件还用 Hunt、Ettercap 举例，并提到某些 Unix 系统可通过 ifconfig -arp 关闭接口自身的常规 ARP 处理。转发给另一端和更改本机接口行为是两项独立操作。

管理员可以为少量固定设备配置静态 ARP 条目，避免它们被动态响应改写。若要为整网所有主机逐一设置，换网卡、调整地址时都需要同步更新，维护成本较高。另一种做法是使用 Arpwatch 监听局域网里的 ARP 消息，保存平常观察到的 IP 与 MAC 对应关系。某个 IP 突然换到另一个 MAC，或在两个 MAC 之间反复切换时，它会通知管理员核查。
